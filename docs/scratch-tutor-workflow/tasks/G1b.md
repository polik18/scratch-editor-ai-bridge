# G1b：摘要缺口修正

## 輸入與前置條件
依賴：G1a。先讀入口 SKILL.md、狀態摘要及本卡；原計畫只按需讀相應段落。確認 source HEAD、dirty 與寫入範圍；未通過依賴不得開工。

## 工作
若 G1a 有缺口，按原計畫第 10 節設計受限摘要，區分 revision、素材、VM、行為及未知；不傳素材 bytes。

## 驗收與輸出
測 stale revision、缺素材、未執行、截斷及隱私；無缺口時 skip 並附 G1a 證據。
記錄具體命令、退出碼、檔案與客觀證據；尚未執行項標 not-run。先寫交接證據，再將狀態設為 done。

## 失敗與恢復
保留其他人的修改；中斷或結果不明先查證再繼續。禁止覆寫原始作品、部署、對外發布或操作帳號。完整限制見入口與原計畫。
