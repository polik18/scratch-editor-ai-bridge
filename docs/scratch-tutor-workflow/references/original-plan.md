## 2. 使用者成果與界線

1. 學生能描述目標、預期與實際結果，選擇要一個提示或較完整的說明；先看到與作品相關的可定位線索，資料不足時知道下一步如何補充。
2. 對有資料支撐的簡單腳本，可看到繁體中文的積木順序及控制結構；明確標註靜態說明、未知及未執行的部分。使用者不必先閱讀整個作品。
3. 教師可取得有可核對依據的詳細說明；學生使用匿名視圖，識別碼對應留在本機或依明確資料契約提供。
4. 維持原始 SB3 保留、局部修改提案與確認、容量界線，以及外部 AI 資料傳送說明。提示文字是模型指令，不保證外部模型遵守；不可把模型答案當成驗證結果。

不在本計畫中自行接入付費 API、宣稱能生成圖片／聲音或自動送出作品，不要求一律產生三種解法；若要擴張素材生成與平台範圍，另行立案。

## 4. T0：可重現基線與教學案例

- 建立自製、可分享的小型測試集，至少涵蓋綠旗定位、按鍵移動、碰撞計分、重複／如果／否則、巢狀運算、廣播、含字串及布林參數的自製積木、未知 extension、缺失證據、重名角色及大型作品。每案記錄作品版本、問題、正確可見積木／值、預期操作、不可推論事項與資料來源。
- 記錄主站和學生頁：提示選項、實際 evidence packet、輸入／輸出限制、被選中的線索、複製內容與學生可見定位方式。對教師引用 ID、無關第一筆積木、同 opcode 多角色及 evidence 超額進行可重播測試；先記錄行為，未重現者標示待查。
- 建立基線表：每案是否找到相關線索、定位正確、是否憑空斷言、是否明示未知、截斷與隱私、回答長度及傳送內容大小；分別記錄 numerator／denominator 和 `not-run`。真實模型或真人未可用時，以測試替身檢查資料契約，但不以它代表教學品質。

**通過條件**：案例及預期可在本機重播；明確列出至少一個教師證據契約失敗測試，以及需要修正或判為未重現的學生提示案例；保存版本與執行命令。無需學生或教師參與即可完成工程基線。

## 5. T1：可靠且分流的證據

- 核對教師與學生提示的實際資料：教師若需引用，使用 packet 內明確存在、無敏感內容的短 ID，建立 observation 到 evidence 的關聯；或移除引用要求並明確採可定位描述，擇一並測試。不得要求模型引用不存在的資料。
- 學生模式持續避免輸出原始角色名稱、block ID、路徑與素材；保留角色代號與畫面順序的可靠對應。變數、廣播、學生輸入等文字仍可能含個資，應確認顯示及複製前提示，不能宣稱全部資料已自動匿名。
- 檢查現行固定最多 36 facts／80 evidence、優先順序及 24,000 字元裁剪是否會遺失問題相關線索。設計明確的已省略數、原因和無足夠資料狀態，避免裁切後 observation 指向不存在的 evidence；處理大量 limitations、巨大文字與重名角色。
- 在證據不足時維持「未知」；若作問題相關排序，先定義可解釋的選取規則與失敗回退，不以字詞匹配代表問題根因。模型不得推斷未測 runtime。

**驗收**：教師每個可引用 ID 均存在且可追溯；學生 packet 不暴露 raw ID／名稱／素材；關聯、上限、截斷、同名、長內容及無證據有正反測試。量測前後 JSON 長度與相關線索保留率；不因新欄位超過既有限額。

## 6. T2：按需求教學與本機提示

- 在獨立學生頁評估以簡明選項提供「給我一點提示／一步步教我／看完整解法」，預設維持目前一步提示；映射到現有 `hintLevel`，避免與主站既有四級互相矛盾。決定文字及預設前，以 T0 操作案例確認對學生是否清楚。
- 修正 `prompt.ts` 中第 1 級「只給一個引導問題」、第 4 級「完整解法」與共同的「兩段、一步、160 字」可能衝突：各程度定義明確字數、步驟及無證據時的回覆，保留簡潔與不猜測原則。完整解法僅在證據足夠時具體說明，必要時請補資料。
- 針對學生頁 `renderFirstHint` 的關鍵字及首筆 opcode 行為，測試相同積木在不同角色、條件或變數下的案例；證據不夠時改成可觀察的檢查建議及不確定說明，避免暗示已找出錯誤。可先提供選擇角色／線索的方式，再按所選範圍縮小，不預設分類器能理解整個遊戲。
- 合理使用技能的比喻、可選小挑戰和反思；不強迫每次問問題，也不每次輸出三種演算法。學生若明確要答案，不強制等待教學確認。

**驗收**：各模式的提示無互斥指令，能保留預期／實際描述與選擇；覆蓋無結果、歧義、完整解法、切換作品、複製失敗及鍵盤操作。用自製案例檢查相關性、可操作性與不虛構；模型表現另依 T4 評估。

## 7. T3：選定腳本的中文說明（候選）

- 先盤點現有 `studentLabel`、Canonical 與 raw graph 的對照、scope、自製積木與不支援 opcode 表現；優先重用既有 parser、capability registry 與原始 block 映射，禁止以技能附錄 Python 取代現有 graph。
- 按使用者選定的角色與一段腳本，呈現事件、積木順序、輸入、巢狀條件、迴圈和 else，清楚顯示未識別／截斷，不把靜態順序誤稱必定發生的執行結果。自製積木以實際 argument IDs 對照型別與值；未知時保留原狀並標記，避免漏參數或猜補。
- 每段對應本機原始定位資訊；匿名輸出與教師視圖分流。控制遞迴深度、循環圖、長字串及輸出預算，大型作品按需載入；不修改原始作品。

**驗收**：以上述 fixture 對照 Scratch 實際可見積木和控制結構，事件、巢狀 if/else、運算、廣播及自製積木參數各有正反例；已支援案例的順序、數值與定位 100% 對照一致，無法判斷者明示未知。重名、畸形圖、未知 extension 與大型資料不凍結、不洩漏原始資料；效能與截斷數據相對 T0 報告。

## 9. G0：goboscript 同題比較

**研究問題**：對從零生成作品，文字程式是否比現有 Canonical IR／ScratchSession 路徑更容易生成、修正及驗證？對既有作品的轉換會造成哪些損失？不得以語法看起來簡單就推定品質較好。

- 使用隔離的本機測試目錄與固定版本，記錄 scratch-mcp 副本來源／雜湊、goboscript、sb2gs、Python、Rust、Bridge 和模型版本。先檢查執行環境與依賴、授權和可用性；安裝依賴僅用隔離環境，不改寫現有專案或使用使用者帳號。不可取得時標 `not-run`，保留可獨立進行的教學工作。
- 共用至少四個可散布、自製的相同需求：按鍵移動、碰撞計分、廣播／多角色、含參數自製積木與巢狀條件；另用較大型合成作品評估擴展性。兩條路徑給相同規格、同一已授權本機模型及一致修復次數／時間預算；保留初次與修復後結果，記錄無法公平控制的差異。
- 分項記錄需求達成、可編譯、Scratch VM 載入、可重播行為斷言、素材 bytes 和視覺檢查、診斷可操作性、修復輪次、耗時與輸入輸出量。每項報告成功／總數與失敗，不以編譯成功或單一 demo 當作可玩性或整體品質。
- 對既有作品另用自製 fixture 比較原始 SB3 → sb2gs → goboscript → SB3：檢查角色、變數 scope、清單、自製積木參數、擴充、素材和 graph，記錄重命名、遺失、版面與行為差異；以原始檔 hash 和各素材內容 hash 驗證。README 明示轉換可能有損，因此不得用此路徑取代 Bridge 原始作品保留式修改；轉換結果僅為另存副本。
- 比較 Bridge 現有 `ScratchSession`、MCP 與 scratch-mcp 的角色與執行位置：現有 MCP 是已開頁面的讀取／待審 patch，ScratchSession 是本機 CLI／程式介面，scratch-mcp 使用外部檔案編輯與工具鏈；不得把 CLI 功能宣稱為 MCP 已提供。

**通過條件**：完成固定案例與可重播報告，將每一項標為 pass／fail／not-run，列可觀察的優缺點與原檔保留證據；根據結果選擇「啟動 G2／僅保留研究／不採用」，說明理由。模型或工具鏈不可用時，不得做優劣結論。

## 10. G1：編譯產物摘要與回饋

- 先對照現有 `src/cli/inspect.ts`、生成報告、素材 catalog／provenance、VM 驗證與 AI 工具輸出，盤點已提供和欠缺的資訊；參考 scratch-mcp `project_summary` 的角色、程式數、素材、圖層、未使用素材與過期產物提示，不重複建造已有能力。
- 對確有缺口的部分設計有版本的精簡摘要：來源 revision、角色與腳本數、素材來源和缺失、編譯與 VM 結果、是否執行場景、限制與已省略內容。只有能確認來源 revision 或內容 hash 時才判定產物與來源相符；若無法判定則標未知，不只依檔案時間宣稱正確。
- 優先以現有 CLI／AI 使用場景評估呈現，依使用者需要考慮學生版與教師版；不外送素材 bytes、原始個資或完整 SB3。保持大小上限、定位方式及已確認／推測／未執行之區分。

**驗收**：自製案例覆蓋新舊 revision、缺素材、未使用素材、未知來源與未執行場景；摘要與 SB3／驗證報告一致，不將靜態統計當行為通過，隱私與截斷符合既有契約。若盤點顯示現有輸出已充分涵蓋，記錄對照並以無需實作結案。

## 11. G2：可選文字生成入口（視 G0 決策）

- 若 G0 顯示可重現收益，先設計獨立、可選的進階生成路徑：文字來源 → 固定版本編譯 → 現有檢查與 VM／行為驗證 → 顯示差異和限制 → 使用者另存。學生既有網頁流程可維持原樣；不得把 goboscript／Rust 變成網站使用的必要條件。
- 明確區分本機 CLI 和瀏覽器可用性，評估工具安裝、版本固定、離線及平台支援、資源上限、錯誤恢復和授權；未驗證前不承諾瀏覽器內執行。來源及產物使用受控工作目錄，不覆寫使用者原檔。
- 保留原始 SB3 的局部 patch、revision、差異審查與確認；已有作品若走有損文字轉換，必須明示損失、保留原檔並另存副本。可編譯與 VM 載入、實際行為及 Scratch 網站匯入分開回報。
- scratch-mcp 的 Scratch 登入、雲端發布及社群工具不屬於此整合範圍；未來如有需求另定資料、帳號與外部操作契約，不讀取既有瀏覽器 session 或自動發文／發布。

**驗收**：重跑 G0 案例並比較實際結果，包含依賴不存在、編譯失敗、取消、過期 revision、有損轉換提醒、原檔及素材保留；使用者確認流程、相關測試與建置通過。僅在此項完成並經實測後才宣稱已支援；未啟動不影響 T0–T4 教學工作包的判定。

## 12. 執行交接

開工時先確認 source 工作樹、dirty 狀態與其他工作樹正在進行的分析器修改；依序從 T0 開始。每個切片記錄實際 HEAD、修改範圍、測試、結果、未測事項與下一步。勿覆寫 `gh-pages` 未提交產物、他人未提交修改或原始學生作品。完成後在適用的 source 專案狀態文件中記錄實際結果，避免把本計畫的待辦寫成已完成。
