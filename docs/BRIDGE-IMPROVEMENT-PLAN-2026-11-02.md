# Scratch AI Bridge 改善計畫：理解、修改與回饋大型作品

日期：2026-11-02  
狀態：**規劃，尚未實施**；已納入網頁體驗與效能研究  
範圍：`packages/scratch-ai-bridge`；Paper Minecraft 是真實測試樣本，不是產品本身或唯一驗收對象。  
AI 接手入口：[執行狀態與交接](BRIDGE-EXECUTION-STATUS.md)；[小上下文任務卡索引](bridge-ai-tasks/README.md)。本文件是總體計畫，狀態檔是本計畫的執行紀錄。

## 1. 目標與成功定義

讓使用者匯入既有 Scratch SB3 後，工具能：

1. **讀取與理解**：呈現角色、腳本、自製積木、資料與事件之間的可追溯關係，對大型作品按需查詢；清楚區分結構事實、推論與未知。
2. **安全修改**：針對明確目標提出局部修改、顯示差異、由使用者確認後套用；保留原檔及無關資料，並以實際執行測試修改效果。
3. **給出有用回饋**：指出相關角色、積木與證據，區分已確認問題與待查線索，不把分析工具自身的限制歸咎作品。
4. **學生能使用的網頁**：依學生正在做的事情提供清楚的下一步，將教師設定及技術資料漸進揭露；大型作品處理有明確進度與可量測的回應時間。
5. **可驗證**：每次交付分別報告結構、資產、VM、畫面與行為結果；未執行的項目標示 `not-run`。

本計畫不保證理解任意作品，也不以單一作品、模型回答、載入成功或測試總數代表完整驗收。自然語言模型、瀏覽器預覽、原始 SB3 修改和 `ScratchSession` 是不同入口；應各自記錄能力。

## 2. 已知基線

依 [Paper Minecraft 實測](PAPER-MINECRAFT-AUDIT-2026-11-02.md)與 [專案診斷](DIAGNOSIS-2026-11-02.md)，以下是 2026-11-02、commit `73ea966d87` 的觀察，執行前需重新量測：

- Paper Minecraft：29 個角色、17,285 個積木；CLI 可讀取但回報 `partial`。AI 摘要超過 24 KB 後失敗；部分角色積木查詢被 graph issue 擋住。
- 已證實至少三個警告涉及 Scratch VM 合法的頂層 variable primitive；另五個自製積木參數警告**原因未定**。
- 局部屬性與一個等待時間可在副本中修改並重新載入，未修改的 745 個 ZIP entries 解壓內容雜湊一致；尚未觀察修改實際效果。
- 主選單可渲染；一次自動點擊後未進入遊戲，原因未定。
- Bridge build 成功、69 測試檔／585 測試通過；browser smoke 因選擇器命中多個面板而中止，CSP IPv6 來源被 Chromium 拒絕；lint 為 1,388 errors、1 warning，Prettier 未執行。
- 原始遊戲保留在使用者桌面，實測產物放工作區外；不將未確認可再散布的完整作品或素材提交至 repo。

## 4. 工作包 P0：恢復測試基線

**問題**：現行 browser smoke 中 `.student-live-patch summary` 命中五個元素，後續流程未跑到；CSP IPv6 source 也有瀏覽器警告。

- 使用面板專屬、可讀且唯一的 selector，加入能偵測同類面板增加時仍精確選中的測試；重新執行整個 Chromium smoke，逐一記錄新暴露的失敗，直到通過或有可重現且獨立的阻塞。
- 檢查 `index.html`、`student-help.html` 的 CSP；依受支援瀏覽器可接受的來源語法修正或有根據地調整，測試 IPv4、localhost 與預期 IPv6 路徑，避免擴大來源權限。區分 CSP 解析警告與實際連線失敗。
- 重現 Paper Minecraft 選單點擊：固定畫面座標、按下時間、啟動等待、錯誤日誌和截圖；必要時用簡單獨立作品對照，定位輸入傳遞、作品時序或其他原因。未定位前不宣稱是任一方缺陷。
- 保存 lint 規則和路徑分類基線；分別執行 ESLint 與 Prettier，建立可比較的後續數字。先處理本計畫修改檔案的新增違規，不以全域關閉規則或大量自動修正假裝清零。

**驗收**：相關回歸測試、完整 Chromium smoke 和 build 均通過且命令與結果可重播；Paper 點擊有明確重現記錄；CSP 測試證明未放寬非預期來源。若完整 smoke 未通過，P0 保持「進行中」或「受阻」，保留失敗與未覆蓋流程，不視為完成；其他瀏覽器未測就明列。

## 5. 工作包 P1：正確處理原始 Scratch 積木

**入口**：`src/core/graph/block-graph.ts` 的 `extractProjectBlockGraphs`；Scratch VM 支援的 SB3 primitive 反序列化可對照 `packages/scratch-vm/src/serialization/sb3.js`。

- 先建立最小自製 fixture，涵蓋頂層 variable/list primitive（含座標和 ID）、一般 object block、巢狀 input、未知或損毀 tuple；比對此 repo 鎖定 VM 的實際接受行為，非一律放行 array。
- 在分析表示和原始 archive 表示之間明確建立映射；合法 primitive 不因缺少 `opcode` 而誤判，保留原始資料、ID、順序及座標。patch/export 不可在替換 block graph 時丟失或重寫無關 primitive。
- 對五個 argument reporter 告警逐一重建父鏈與 procedure 原型，區分合法自製積木、孤立積木、真實資料損毀及分析器無法判定；只按證據修正，未知維持保守標示。
- 在可定位的前提下，評估能否只拒絕受損的子圖而非整個角色；不為解除限制放寬對有風險 graph patch 的完整性檢查。

**驗收**：

- 合法 primitive 的最小案例通過 graph、CLI inspect、raw AI 讀取、無關 block patch、export 和 VM reload；未知／畸形資料仍被安全拒絕或標記。
- 修改前後獨立比較 JSON：除了目標欄位及允許的必要變化，其餘 subtree 一致；所有非 `project.json` ZIP entries 的解壓內容 SHA-256 一致，明示不保證 ZIP 位元組完全一致。
- 重跑 Paper Minecraft，記錄原先三類 primitive 告警是否消失、各 target 仍有哪些原因阻止 patch；五個參數告警逐項提供判斷或標記待查。不宣稱 `partial` 必定變成 `ok`。

## 6. 工作包 P2：大型作品的分頁理解

**入口**：`src/core/ai/raw-tool-core.ts`、`src/main.ts` 的 raw AI 與 MCP 工具。

- 以預算化最小摘要取代「先拼完整 24 KB、超過就失敗」：優先包含作品 revision、總覽計數、精簡 target 索引、已省略範圍、可用查詢方式；保留 byte 上限，不傳送素材 bytes、雲端變數或無關清單值。
- 沿用並完善 target／variable／block 分頁，支援按 target 名稱、積木 ID、opcode、事件、自製積木定義及引用定位相關上下文；每頁回傳明確 cursor、total、截斷、版本與可讀取範圍。避免以任意批次猜測語意。
- 讓摘要過大、單筆超大、缺失目標、重名、舊 revision 等狀態有可執行的回應；revision 改變後拒絕舊 cursor 和 patch。
- 確認 UI、工具呼叫及 MCP host 對摘要／分頁使用相同能力契約；限制單頁、總資料量和請求回合，避免整個作品一次塞入模型。

**驗收**：小型、30 角色以上、超過舊摘要上限、巨大單一欄位、重名角色和 stale revision 的測試通過。Paper Minecraft 可取得受限摘要並循序查到指定 `Tiles` 廣播與等待積木、`Generator` 目標；顯示完整／部分及省略原因。提供頁面與 byte 數、延遲和記憶體的測量結果，不以可讀到文字宣稱理解遊戲。

## 7. 工作包 P3：可定位、可信的回饋

- 將可確認事實、靜態推測、未支援／未分析及執行時結果分開；說明 coverage 的定義與分母、被截斷的證據數量。不得因合法 primitive 的相容問題扣作品分數。
- 每項技術回饋附原始 target 名稱或穩定識別、積木 ID、opcode／位置、證據與回到編輯器的方法；學生版可以匿名，但需有教師／本機可定位的對照，並明確說明隱私界線。
- 對未連接腳本與自製積木參數等，說明可能是草稿、結構限制或需人工確認；合併重複項目，優先顯示可操作、具區分度的建議，不將猜測寫成事實。
- 建立最小標註 corpus：包含合法、故意損壞、未接草稿、有效自製積木及不同規模作品；由可追溯的人工判定核對，不使用未經確認的 Paper Minecraft 告警當真值。

**驗收**：回饋能追溯到輸入實體，統計產出數、抽查數、確認正確數、誤報數、未知數；每種標註類型至少一個正反案例。Paper Minecraft 的回饋清楚區分已知工具誤報、未判定及可操作建議；不以分數、100% coverage 或總警告數宣稱作品好壞。

## 8. 工作包 P4：修改安全性與實際行為

- 定義修改生命週期：讀取原始 archive／計算 revision → 定位與讀取範圍 → 提案與 before/after diff → graph／schema 檢查 → 使用者確認 → 套用到新版本 → 驗證 → 另存。保留最後正常版本；拒絕 stale revision、歧義目標及未確認的破壞性變更。
- 至少涵蓋角色屬性、非 cloud scalar、既有積木欄位／輸入；單次修改範圍遵守現有契約。優先原始 SB3 路徑保留未知欄位及素材，不因便利而先轉 Canonical 再重建。
- 加入可重播 scenario：明確初始檔案、隨機性／時間控制、按鍵和滑鼠時間、觀察的變數／角色／畫面，以及每個斷言對應需求。用簡單合成作品證明成功與失敗，再針對 Paper Minecraft 驗證主選單、進入遊戲及一項經理解的具體修改；不要把單純改等待值或 VM reload 當成效果驗證。
- 角色初始值可能被綠旗腳本覆寫；修改回饋需呈現這個可證實的風險，並以執行結果判斷。

**驗收**：成功、拒絕、取消、過期 revision、錯誤 graph、原作未知欄位、資產保留、匯出／重載、初始化覆寫以及行為 before/after 均有測試；對使用者提供的真實作品輸出副本，核對原檔 SHA-256 未變。`runtime-behavior` 只有實際 scenario 與斷言通過才標記 pass；無 scenario 保持 `not-run`。

## 9. 工作包 P5：真實模型及整合評估

- 先以 fake provider 測試工具使用、分頁、修正失敗、資料上限、取消與未確認不得套用，再用使用者允許的本機模型做真實端到端評估；記錄模型、配置、樣本、輸入、回合、耗時和錯誤。不得把模型輸出本身當驗證。
- 至少使用簡單、含自製積木、具清單／事件互動及大型作品等不同類型案例；各案例先寫需求和可觀察的預期結果，記錄不可評估項目。Paper Minecraft 僅作使用者本機案例；可散布測試 fixture 以自製或確認授權素材替代。
- 對「理解」「給回饋」「提出安全修改」「修改達成目標」分別記成功數／總數及失敗原因；逐案保留能重播的結果與 revision。真實 MCP host、網頁、CLI 或跨裝置只在各自實測後宣稱。

**驗收**：固定案例與評估條件可重跑；所有結果包含分母、修復輪次、未完成數及限制。若模型、設備或授權不可用，標示 `not-run` 與原因，不以模擬 provider 代替真實驗收。

## 9A. 工作包 U0：網頁現況研究與量測

**檢視範圍**：主要網站 `index.html`／`src/main.ts`，學生解惑頁 `student-help.html`，及實際預覽 iframe；將 `src/ui/preview.html` 視為另一入口，先確認其定位，不能假設兩套介面行為相同。

### 已有的程式證據

- 主站預設是「用 AI 做 Scratch」，要求學生在網站和外部 AI 間複製指令、回貼玩法 brief，再貼完整 JSON；大型作品功能還顯示 target、片段 ID 及 JSON。這些是程式可見的流程，是否、在哪一步讓不同年齡學生困惑仍需實測。
- 匯入作品的畫面同時有結構參考分、行為、回饋、角色清單、AI 問題與技術輸出；試玩按鈕位於分析流程後段，另有獨立學生解惑頁。需要評估使用者能否快速找到想做的事，並區分學生與教師的需求。
- `src/main.ts` 的匯入流程在同一工作流程執行 decompile、靜態分析、作品地圖、回饋及評分；`renderAnalysis` 建立角色與程式清單、對每個腳本反覆篩選 evidence，並預先對 Canonical／分析等技術結果執行 `JSON.stringify`。這些是大型作品可能的負擔，尚未證明哪一段造成卡頓。
- 現有 `tests/performance/bridge.bench.ts` 主要量 Node 中 100–2,000 積木的處理與 4 MiB 素材匯入；bundle 檢查統計打包檔大小，兩者都不能代表大型作品在學校電腦上的瀏覽器操作時間、主執行緒阻塞或記憶體。
- 前次 build 的 JS 合計約 5.77 MiB raw／2.22 MiB gzip 是**全部 bundle 檔案統計**，不是首頁實際下載量；renderer、VM 等是否在首次載入時取得，須由瀏覽器網路紀錄確認。
- 既有 [學生可用性驗收腳本](../packages/scratch-ai-bridge/docs/student-usability-plan.md) 曾規劃學生測試；依既有文件，使用者曾豁免真人教學驗收，故真人觀察仍是未驗證，不把本計畫當成撤銷豁免或發布前必須招募學生的指令。

### 量測方案

1. 分別記錄首頁冷／暖載入、上傳至可操作、首個有用結果、展開角色清單、搜尋、預覽首畫面與操作回應。分段量測解壓、graph／分析、DOM 建立、JSON 輸出和 renderer；記錄 long task、主執行緒耗時、DOM 節點數及可取得的記憶體。明示瀏覽器記憶體 API 不可用時的替代方法或 `not-run`。
2. 以小型自製作品、可散布的合成大型作品及本機 Paper Minecraft 三種規模測試。記錄設備、記憶體、系統、瀏覽器、CPU／網路限制、快取狀態、版本及各階段資料量；至少冷／暖各重複 5 次，報中位數、最慢值與失敗，不以單次或本機高階裝置推論全部學校電腦。
3. 設立具體效能預算：先保存改善前量測，再依代表性學校設備及實際數據設定並記錄可重現門檻；候選首批目標為小作品匯入到首個有用結果與大型作品匯入完成時間各比同裝置基線減少至少 20%，以及減少長任務次數／總時長。若基線太小、波動過大或造成其他退步，先說明並調整門檻，不憑空宣稱達標。
4. 用桌面與窄螢幕，沿「匯入 → 看見結果 → 試玩 → 提問 → 檢查修改 → 下載」逐步走查；另走生成流程、學生解惑頁，以及無模型／不可用、檔案無效、等待或失敗情況。記錄每個狀態的下一步、主要按鈕、術語和實際點擊數；自動化只證明流程，不代表學生看得懂。

**驗收**：取得可重跑的基線表與 trace／摘要，列出量測環境、數據分布與未測項；至少定位一個實際耗時熱點，才將其列為已確認效能原因。若無可代表的學校設備或真人學生紀錄，分別標示未驗證。

## 9B. 工作包 U1：學生導向的網頁流程

### 資訊架構與互動

- 主入口以學生意圖組織，如「開啟 Scratch 作品」「建立作品」「我遇到問題」；對既有作品提供明確的「看懂作品、試玩、提出問題、檢查建議、另存」路徑。以上為待驗證設計，不先認定某個版面就是最佳。
- 首畫面每次只強調與目前任務相關的主要動作；上傳後顯示作品名稱、處理進度、可看見的結果和下一步。編輯、儲存、模型與作品來源狀態應一致；明確標示「尚未執行」「已試玩」「建議待確認」與失敗原因。
- 本機模型、MCP、同步、進階圖結構、JSON、分數與批次工具放在可找到的教師／進階區，保留既有能力及必要權限確認。學生不需要手動理解 Canonical IR 或 raw patch 才能走主要流程；無模型時仍能本機檢視、試玩及得到有證據的基礎提示。
- 將外部 AI 的複製／貼上呈現為清楚的替代路徑；若可使用已設定的本機 AI，則引導學生以一句話提問並顯示是否連線、要傳送什麼、候選修改與確認動作。不得暗示有 AI 回答或修改已自動完成。
- 用「你想做什麼 → 看到了什麼 → 試一步 → 重新觀察」組織回饋；同時保留角色與積木定位、依據、未知資訊及教師的技術詳情。對靜態參考分避免呈現為正式成績。
- 提供 keyboard 操作、可見焦點、狀態通知、錯誤恢復、窄螢幕及螢幕閱讀器語意；從頭至尾保持原作品可下載，修改之前顯示差異與確認，讓學生知道下載位置與 Scratch 後續開啟方式。
- 將主站和學生解惑頁的角色、對象、鏈結及相同任務的文案整理一致；先確認實際入口流量與用途，再決定是否合併，避免破壞既有教師連結。

### 驗收

- 建立無模型、fake provider、有模型連線但失敗、無效 SB3、部分分析和取消修改等瀏覽器任務，驗證主要動作、焦點／狀態、原檔保留和不自動提交。生成與匯入流程分別測試，手機／窄畫面與鍵盤測試不得互相替代。
- 沿用既有可用性腳本的任務與指標作為候選，包含獨立完成、時間、求助、誤解與下一步辨識；可先由內部走查及自動化提供工程證據。若將來使用者安排真人測試，再依學校隱私要求執行並記錄母數；無真人資料時只稱「工程流程已驗證」，不聲稱學生已看懂。

## 9C. 工作包 U2：網頁效能改善

依 U0 trace 排序並逐項處理，以下為**待量測的候選**，不是已證實的根因：

1. **按需執行／展示**：先提供有用的概要；教師展開技術報告或下載時才序列化大型 JSON。角色、腳本及 evidence 使用索引、分頁或虛擬清單，避免每段腳本重複掃描全部 evidence；保證搜尋、定位、匯出和無障礙結果完整。
2. **降低主執行緒阻塞**：評估將解壓、分析及摘要移至 Web Worker 或可取消的分段任務；先檢查可序列化資料、複製成本與瀏覽器支援，不假設 Worker 一定較快。支援進度、取消、切換檔案後丟棄舊結果、錯誤恢復與釋放資源。
3. **減少重複工作**：同一版本重用安全的分析／預覽結果；以 revision 為鍵，修改、重新匯入、刪除或不同使用者檔案時正確失效，避免顯示舊資料或混入另一作品。
4. **按使用時載入**：依實際網路及 bundle trace 評估按需載入 VM、renderer 與進階功能；測試離線 service worker、弱網、CSP 與現有預覽行為，避免只移動檔案而增加實際等待。
5. **大型檔案邊界**：維持現有 ZIP、JSON、素材與記憶體防護上限，顯示可理解的進度與錯誤；不得為了通過測試直接放寬上限或將作品內容送往服務端。

**驗收**：相同設備、資料及條件下與 U0 基線逐項對照；提供每階段時間、long task／回應、記憶體可用性、首屏實際網路與失敗數。達成已記錄的效能門檻且不回退：分頁／搜尋結果、分析與原始檔保留、keyboard、取消、重複切換及預覽皆通過回歸。原始作品及大型測試產物維持工作區外。

## 9D. 工作包 A0／A1：Scratch 素材庫的理解、選擇與使用

### 問題與已證實基線

詳細證據見 [Scratch 素材庫調查](SCRATCH-ASSET-LIBRARY-AUDIT-2026-11-02.md)。同一 checkout 的 Scratch GUI 已有 343 角色、915 造型、85 背景、354 音效的 catalog，但索引不是完整素材 bytes。Bridge 主網頁未接入 catalog，生成 GameDesign 的造型名也沒有解析成對應 Scratch 素材。實測指定 `Abby-a` 和 `Arctic` 仍得到不同 asset ID 的自動圖，報告卻是 success；因此使用者難以知道看到的是哪種來源。已有 SB3 內嵌素材可保留及渲染，不代表系統具備圖片／聲音語意理解。

### A0：素材來源與契約

- 以本 repo 版本盤點四種 catalog 及其資料結構：角色與其多造型／音效、標籤、格式、ID、旋轉中心、bitmap resolution、音訊取樣率與樣本數；記錄 catalog revision 與來源。角色可能還有腳本或其他資料，決定並標明匯入範圍，不把角色模板等同單一造型。
- 評估採用 GUI 既有介面或讓 Bridge 重用 catalog 與可攜式素材解析器；驗證相關授權與來源服務使用條件，先核實網路、CORS、可用性、快取與離線行為。不得把目前目錄清單誤說成本機完整素材包；不引入未經核實的整庫複製或外部付費服務。
- 定義 library reference：明確的類型、版本與穩定 asset ID，名稱只做顯示／搜尋。處理重名、相同 bytes 多條目、找不到或不可用版本；不能按模糊名稱偷偷選第一筆。保留使用者自行上傳素材與既有 SB3 原始資料。
- 將素材 provenance 區分為 Scratch catalog 精確匹配、使用者素材、已提供素材資料、自動生成／替代素材、未知；以 `md5ext` 與 bytes 驗證 catalog match，標示 catalog 版本。名稱、tag 或模型描述不可冒充實際內容證明。

### A1：搜尋、使用與辨識

- 在學生操作流程中加入可搜尋及預覽的「角色／造型／背景／音效」選擇，提供圖示或聲音試聽、類型、清楚的名稱及選取確認；顯示載入、無網路、缺檔和重試狀態。顯示中文與原名（有對應時），保留分類與無障礙操作；人工建立翻譯不可冒充官方翻譯。
- 生成與修改流程接受經選擇的 catalog reference；按需取得並驗證 bytes、格式與 MD5，維持角色多造型、背景中心及音訊資訊，嵌入最終 SB3；輸出後離線重新載入。取得失敗時明確報錯或讓使用者確認替代，**不可把替代圖／靜音冒充選中的素材**。只有名字而未明確選擇官方項目時，顯示來源及任何自動生成結果。
- 對已匯入作品建立安全的素材清單：歸屬 target、名稱、種類、格式、checksum、缺失狀態、縮圖／音訊預聽與已知 catalog 精確匹配；保留同一 bytes 對應多個 catalog 名稱的歧義。非 catalog 匹配素材可檢視，但不能只憑 MD5、檔名或 tag 斷言它畫了什麼／聲音內容。
- 提供 AI 可按類別、名稱、標籤、ID 分頁查詢與選擇建議的受限工具；返回必要 metadata 與版本，避免一次傳整庫、作品素材 bytes 或學生資料。修改仍需使用者審閱，套用前檢查 revision；非視覺模型只能依 metadata／使用者描述回答，若以明確啟用的本機多模態模型描述自製素材，清楚標示推測、模型與限制。
- 按需載入縮圖與媒體，符合 U0／U2 的效能及離線驗證；網路可用性和內容來源在 UI 中清楚呈現。不得把 Scratch 官方素材服務視為已授權任意全庫鏡像或永久可用。

### 驗收

1. 合成及具來源許可的 fixture 覆蓋角色多造型、背景、音效、不同 bitmap resolution／旋轉中心、重名、多 catalog 匹配、缺檔、MD5 錯誤、損毀、網路失敗與離線。確認選擇與渲染／試聽一致，SB3 的全部素材存在且 MD5 匹配、metadata 不遺失、Scratch VM reload 成功。
2. 使用本地 catalog 的 `Abby-a` 與 `Arctic` 重現先前錯配案例：明確選擇官方項目後輸出 asset ID／bytes 與所選來源一致；若不可取得應明確失敗或要求確認替代，不能成功卻靜默輸出替代品。也測試單純文字名稱的既有行為及清楚來源標示，避免不相容。
3. 對 Paper Minecraft 重新盤點素材及匹配結果：保持 748、90 為原作品參照基準；以本版 catalog 精確匹配結果和未匹配範圍檢驗，不把未命中視為破損。手動篩選一部分素材檢查縮圖／試聽；不聲稱已理解全部素材語意。
4. 瀏覽器任務覆蓋搜尋、預覽、選擇、確認、另存、失敗與離線；fake provider 驗證 AI 分頁查詢和不越權修改，真實模型另依 P5 驗收。記錄實際網路來源、上傳／外送範圍、授權依據與效能結果。

## 12. AI 執行與交接契約

### 12.1 開工前和工作包狀態

1. 先讀適用的 `AGENTS.md`、本計畫及 [執行狀態](BRIDGE-EXECUTION-STATUS.md)；執行 `git status --short`、`git log -1 --oneline`、`node --version`、`npm --version`，檢查目標檔案有無未提交修改、既有測試與可能的其他寫入者。不要假設狀態欄代表鎖；若有衝突的活躍 owner，先避免同檔寫入並查明權威狀態。
2. `.nvmrc` 記載 Node 24.21.0；現有 shell 曾為 Node 26.8.2。優先以已安裝的指定版本重跑基線，記錄命令實際解析到的版本；若不存在，不自行更換全域環境，明示環境差異並繼續可行的檢查。基準與改善量測須相同環境。
3. 狀態只用「未開始／進行中／通過／受阻」；通過需有本計畫對應驗收的可重播證據。每項測試與外部驗收單列 pass／fail／not-run（附原因）。缺少模型、實體裝置、素材服務或真人觀察時，只將依賴該證據的項目標示 not-run／受阻；不阻擋與它無關的工作，不得把它算作 pass。
4. 每次取一個有明確邊界的小切片：記下目的、涉及檔案、原始行為、失敗測試、修改、測試命令和退出碼。完成或交接時更新狀態檔；保留更早實測、其他人的修改和使用者原始作品。無百分比估算，除非明確定義分母。
5. 預設使用單一執行者；只有使用者或適用指令明確要求並行才委派。並行時在狀態檔記錄 owner、檔案範圍、起始 revision、依賴和交付；先處理共同檔案整合，禁止同時重寫同一入口。
