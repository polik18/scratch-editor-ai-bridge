## 1.【動畫】淡水河《時空渡船：淡水河的故事》

**結果**：status `success`、playtestStatus `pass`、seconds 119（目標 120），2 幕，建置 2 次。第一次 108 秒，在第二幕補了 3 行對白後到 119 秒。

**與提示詞的差距**
- 「第 60 秒發送廣播 [切換現代]」：換場由工具自動處理，不能自訂廣播名稱，也不能指定秒數。只能靠第一幕的長度湊（估算約 59～60 秒換場，報告沒有寫實際值）。
- 「老渡船伯換成現代裝扮」：沒有「換造型」動作，只有「動起來」（輪流換造型）。改成第二幕用另一個角色「現代老渡船伯」（同樣是 Dan），所以其實看起來沒換裝。
- 「背景標題出現淡水河」：背景只能選內建的圖，不能在背景上寫字。改用片頭標題和第一句旁白「清代淡水港：淡水河口……」。
- 背景「清代淡水港」用「河口」，「現代淡水河濱公園」用「城市」，都只是大概接近，沒有公園類的內建背景可選。
- 「請輸出角色清單、時間軸、核心積木結構」：工具只產生 .sb3，不會輸出時間軸或積木說明文件。

**不好用的地方**
- 報告只給全長 `seconds`，**沒有每一幕的開始秒數**。提示詞要求「第 60 秒換場」，我只能自己猜旁白一句大約 4 秒、再倒推，沒辦法確認。
- 「旁白」不能寫秒數（格式只說說／想可以加 N秒），旁白佔多久要用總長反推。
- `做不到` 欄位在動畫格式（`guide story`）裡沒有，我照遊戲格式寫進去，建置**完全沒有提示**，也沒出現在報告裡。不知道是被接受還是被忽略。
- 指令會把大量 scratch-vm 的 `WARN No rendering module present…` 印在 stderr，`--silent` 也擋不住；不加 `2>/dev/null` 的話 JSON 被淹沒在幾十行警告後面。

**小模型會卡住的地方**
- 不知道每行要幾秒，就會一直「太短／太長」來回試。片長差多少秒 feedback 會說，但是「該加在哪一幕」不會說，小模型很可能把對白全加在同一幕，換場時間就偏掉。
- 「換裝」這種需求，小模型很可能自己發明 `老渡船伯 換造型 現代` 這種動作，然後被略過（或被當成看不懂）。

**改善建議**
- 報告加每幕的 `start`／`seconds`，例如 `scenes: [{name, start: 4, seconds: 55.5}]`。
- 每一幕可以寫 `"秒數": 55` 或 `"開始": 60`，工具自動補「等」湊到指定秒數。
- 新增「角色 換造型 N／換成 角色名稱的造型」動作，以及「背景上的標題字卡」（例如 `字卡 淡水河`）。
- `guide story` 要寫清楚有沒有 `做不到` 欄位；有的話，報告要列出來。
- 把 scratch-vm 的 WARN 關掉或只寫到 `_過程/`。

## 2.【遊戲】瑠公圳《尋找消失的水道：瑠公圳探險》

**結果**：status `success`、playtestStatus **`fail`**，2 關，正式建置 2 次（另在暫存資料夾做 1 次實驗確認原因）。唯一失敗的項目是「點擊得分／點到『瑠公圳遺跡』會得分（實際 0）」，我判斷是**試玩誤判**（原因見下），遊戲本身的開場、換關、第二關過關畫面、計時都通過。

**與提示詞的差距**
- 「空白鍵挖沙」：空白鍵只能射子彈，改成郭錫瑠走過去碰到泥沙就清除（收集品，每個 1 分）。
- 「將水引導入農田」：沒有水流動畫，只畫一個「農田」角色（沒有行為）當裝飾。
- 「廣播 [關卡2]、[遊戲勝利]」：換關和勝利畫面由工具自動處理，不能自訂廣播名稱。
- 「現代地圖」：不能指定第二關的背景圖。
- 第二關過關條件寫成 `分數 >= 13`（第一關 10 分＋3 處遺跡），因為規定「第二關的過關分數要比第一關高」；不能寫「第二關找到 3 個」。
- 60 秒限時：`設定.時間` 是整個遊戲共用，不確定第二關會不會重新計時。

**不好用的地方**
- **試玩誤判**：「點擊目標」只畫在第二關時，試玩會在第一關點擊，結果 0 分，判為失敗。我另外做了一份「第一關也放一個遺跡」的實驗版，試玩就通過了，證實是試玩只測第一關。feedback 的提示「它可能沒有出現，或出現的時間太短」把人導向錯誤方向，照建議改不了。
- **規則的「說」不能有全形逗號**：`說 挖開泥沙，瑠公圳的水流進來了！` 被拆成兩個動作，後半段報「看不懂動作『瑠公圳的水流進來了！』」。中文句子幾乎都會有逗號，guide 沒提醒。
- 「說明超過 22 個字會自動換行」沒有說是第幾行，只能自己數每一行的字數。
- 第二關沒有畫玩家，工具自動把郭錫瑠放在左上角（`PLAYER_AUTO_PLACED`）。純點擊的關卡也會冒出一個可以走動的玩家，我沒辦法把他拿掉。
- 實驗時把描述檔放在 `output/游智盃/tmp/exp2/exp2.spec.json`，`.sb3` **沒有放在描述檔旁邊**，而是用標題在 `games/` 下開了一個新資料夾，還把描述檔複製過去。這是文件說的規則（資料夾名稱要等於檔名），但很容易誤會，事後要手動清掉。

**小模型會卡住的地方**
- 會照 feedback 去改「出現時間」或「停留」參數，但根本不是原因，會一直重試到上限。
- 對白裡的全形逗號幾乎一定會寫，被拆開後的警告不容易看懂。
- 不會想到「第二關過關分數要累加第一關」，很可能寫 `分數 >= 3`。

**改善建議**
- 試玩的「點擊得分」「接住掉落物」等行為檢查，要在**角色實際出現的那一關**測（先讓第一關過關再測）。
- 「說」後面的文字整段當成一句，只用半形逗號或「,」分隔動作；或在 guide 明寫「說的內容不能有逗號」。
- 每關可以寫自己的「時間」和「過關: 點到 瑠公圳遺跡 3 次」這類以關卡為單位的條件。
- 支援「某一關沒有玩家」。
- 長度警告要寫是第幾行、幾個字。

## 3.【動畫】基隆河《壺穴裡的小石魚》

**結果**：status `success`、playtestStatus `pass`、seconds 90（目標 90），2 幕，建置 2 次（第一次 93 秒，刪掉一個「等 2秒」、縮 1 秒對白）。

**與提示詞的差距**
- 「第 45 秒發送廣播 [河道改建]」：同第 1 號，只能用第一幕長度估（約 44～45 秒），無法確認。
- 「背景特效」：沒有濾鏡／特效動作，只有自動的淡出淡入。
- 「角色造型切換」：只能用「動起來」輪流換造型。
- 「字卡出現『基隆河特有地形：壺穴』」：用旁白第一句和片尾卡第一行代替。
- 背景「壺穴溪谷」用「溪流」，「截彎取直後的河道」用「城市」，沒有河道工程類的背景。

**事實存疑（照提示詞寫，未自行更正）**
- 提示詞寫「截灣取直」，一般寫法是「截彎取直」。我在作品裡用「截彎取直」。
- 「全世界著名的壺穴景觀」偏誇大；基隆河上游（平溪、暖暖一帶）的壺穴在台灣有名，但「全世界著名」需查證。對白照提示詞原文保留。
- 基隆河截彎取直主要在台北市下游河段，和上游的壺穴不在同一段，劇情「同一條魚從壺穴到截彎取直河道」在地理上有跳躍。

**不好用的地方**
- 一樣不知道每幕幾秒，只能整部試一次再微調。
- 片尾「結尾」最多顯示幾行沒寫（資料來源寫「顯示前三筆」，結尾沒寫），我寫了 3 行不確定是否都會顯示。

**小模型會卡住的地方**
- 只有一個角色時，動作很容易寫成一長串「說」，片長不夠時會加很多「等」，畫面會很空。工具不會提醒「畫面太久沒有變化」。

**改善建議**
- 加背景特效動作（例如 `背景 變暗`、`背景 波紋`），和字卡（大字標題）動作。
- 報告列每幕秒數（同第 1 號）。

## 4.【遊戲】新店溪《香魚的回家大作戰》

**結果**：status `success`、playtestStatus `pass`，2 關，建置 4 次（另在暫存資料夾做 1 次實驗）。

| 次數 | 改了什麼 | 試玩結果 |
|------|---------|---------|
| 1 | 第二關畫懸空的 3 層平台 | 第二關沒過關；魚道（向左飄）接不到 |
| 2 | 第二關改成從地面堆起來的 3 階樓梯 | 換關全過；魚道仍接不到（實際 -10，接到垃圾） |
| 3 | 跳躍改「高」、魚道間隔改 2 秒 | 魚道仍接不到 |
| 4 | 魚道改成畫在地圖上的收集品（4 個 × 20 分） | 全部通過 |

**與提示詞的差距**
- 「上下鍵控制香魚」：一個作品只能有一個玩家，第二關要跳，只好兩關都用「平台移動」：左右鍵移動、上鍵跳，沒有下鍵。
- 「橫向捲軸」：舞台不會捲動。垃圾、污水改成「掉落物 方向 左」從右邊流過來；魚道改畫在地圖上的固定位置。
- 「垃圾 -10 分」：用規則 `碰到 垃圾 → 分數 -10`；另外加「污水」當危險物（扣命），因為提示詞要求有「生命值」變數。
- 「30 秒內滿 50 分過關」：`設定.時間` 30 秒是整個遊戲共用，不能只限第一關。
- 「新店溪水壩魚道」只出現在關卡名稱，沒有水壩圖案；「廣播 [過關]」由工具自動處理。
- 「跳躍物理模擬」：用內建的平台跳躍，不能調重力。

**不好用的地方**
- **向左／向右的掉落物，試玩用「左右移動去接」的方法測**，平台玩家在地上永遠接不到從空中飄過的東西，feedback 寫「魚道沒有掉下來，或玩家碰到它也不會得分」，兩個原因都不對。我也不確定實際遊戲裡這是不是真的接不到（出現的高度不知道），只好改設計避開。
- 第一次第二關失敗時，feedback 只說「第二關過關後沒有出現過關畫面」，**沒說是自動玩家沒走到終點**；要自己打開 `_過程/*.report.json` 看 `trace`（時間、x、y 座標陣列），才發現玩家一直在地面走、從平台底下穿過去，從來沒跳。文件說「未過關時報告會附軌跡」，但軌跡只在 report.json 裡，回傳的 JSON 摘要裡看不出來。
- 編譯前檢查說會估算「到不到得了終點」，但懸空平台那一版沒有任何「注意」，直接進試玩才失敗。
- 只畫在第一關圖例、不畫在地圖上的掉落物，會不會在第二關出現？文件沒說。我把垃圾、污水只寫在第一關圖例，看起來第二關沒受影響，但不確定。
- 「規則 `碰到 垃圾 → 分數 -10`」會不會讓垃圾消失、會不會連續扣分，文件沒說，試玩也不測。

**小模型會卡住的地方**
- 「上下鍵」＋「跳躍」同時出現時，小模型很可能寫兩個玩家（一關一個），或在第二關的「角色」裡重新定義玩家。
- 畫平台關卡時，很可能畫懸空的平台（我第一次也是），自動玩家不會往上跳，會反覆失敗，而 feedback 看不出原因。
- 掉落物方向「左」＋收集品，在平台遊戲裡試玩一定失敗；小模型會照 feedback 改速度、間隔，改不好。

**改善建議**
- 一個玩家可以在不同關卡換移動方式（例如第二關 `"玩家行為": 平台移動`）。
- 每關自己的 `時間`。
- 試玩依方向測掉落物：方向左／右時，玩家移動到同一高度去接；平台玩家就跳起來接。
- 第二關沒過關時，feedback 要說「自動玩家停在 (x, y)，離終點還有 N 格，可能要跳上平台」；把軌跡摘要放進 feedback。
- 編譯前的可達性檢查對「懸空平台、沒有可以起跳的牆」給出警告。
- 新增「捲軸」行為或「背景水流往左移」效果。

- 警告訊息說「找不到符合『老竹筏』」，沒說我寫的 `Rowboat` 不存在，也沒列出相近的名稱（例如 Sailboat）。

- 一定會寫中文外觀或不存在的英文名（Raft、Train、MRT、Boy、Girl），而且因為 feedback 空白、status 成功，根本不知道要改。

**改善建議**
- `guide story` 附上可用角色清單（至少依類別：人物、動物、交通工具、物品），或提供 `bridge -- assets 船` 查詢指令。
- 外觀找不到時放進 `feedback`，並建議最接近的 3 個名稱。
- 加入幾個台灣河川常用的程式畫圖造型：竹筏、列車、橋、水壩。

## 整體

### 最常見的問題
1. **時間點對不上**：5 件裡 3 部動畫都要求「第 N 秒廣播換場」，工具既不能指定換場秒數，也不報告每幕秒數，只能猜旁白長度再倒推。
2. **試玩誤判，feedback 指錯方向**：第 2 號（點擊目標只在第二關）、第 4 號（橫向掉落物、懸空平台）都是試玩方法本身的限制，feedback 的「可能原因」都不對，照改無效。
3. **只看 feedback 會漏掉問題**：外觀猜錯（`fixed`）不進 feedback；自動玩家的軌跡只在 `_過程/` 的 report.json。
4. **關卡層級的設定不夠**：時間、玩家移動方式、背景都只能整個遊戲共用，「第一關 30 秒」「第二關換成點擊」「第二關跳躍」都只能將就。
5. **提示詞常見的 Scratch 用語（廣播、換造型、背景字卡、特效）都沒有對應**，只能放進「做不到」；動畫格式又沒有 `做不到` 欄位。
6. 小地方：全形逗號會把「說」切開、說明行過長不告訴第幾行、stderr 大量 WARN、spec 放錯資料夾會在 `games/` 另開新資料夾。

### 最想要的 3 個新功能
1. **動畫的時間控制**：每幕可指定 `秒數`／`開始`，工具自動補等待；報告列出每幕開始秒數。也讓作品裡真的發出指定名稱的廣播（例如 `廣播 切換現代`），方便老師對照提示詞。
2. **關卡層級設定**：每關自己的 `時間`、`背景`、玩家移動方式（俯視／平台／無玩家），以及「點到 X 達 N 次 → 過關」這種以關為單位的條件。
