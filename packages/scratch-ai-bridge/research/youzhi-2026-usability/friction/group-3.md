## 11. 【動畫】柳川：《柳樹下的記憶交響曲》

**結果**：status `success`、playtestStatus `pass`、seconds **100**（目標 100）。建置 3 次（第 1 次 106 秒 → 調整等待與對白秒數 → 100 秒；第 3 次只是加入「做不到」欄位測試）。

**與提示詞的差距**
- 指定台詞「看著『柳川』從以前的運河變成排水溝……」原文放入；「台中柳川海綿城市生態工法」出現在兩幕對話中。
- 「第 50 秒發送廣播 [海綿城市]」：Story Spec 沒有廣播語法。工具內部會用自動命名的訊息換場（`inspect` 看得到「送出角色訊息」），但不能指定名稱與時間點。改成反覆調整第一幕長度，讓換場落在約 50 秒（估算約 50～51 秒，報告沒有逐幕時間，無法確認）。
- Backdrop1（早期吊腳樓與舊河道）、Backdrop2（海綿城市綠帶）：沒有對應素材，改用內建「河流」「城市」，用旁白補充說明畫面。
- 「透水鋪面、防洪景觀」只能用對白和旁白介紹，沒有畫面元素。

**不好用的地方**
- 報告只有總長 `seconds`，**沒有每一幕的秒數**。要讓換場落在第 50 秒，只能自己反推「旁白」自動計時（從兩次結果反推約 4～6 秒／句，與字數有關，說明沒寫規則）。
- `--silent` 仍然有大量 `scratch-vm WARN No rendering module present…` 寫到 stderr，輸出很長，要自己加 `2>/dev/null` 才看得到 JSON。
- Story Spec 的「做不到」欄位**被靜默忽略**：報告沒有 `unsupported` 欄位，也沒有任何提示；`guide story` 也沒說這欄可不可以寫。

**小模型會卡住的地方**
- 「第 50 秒廣播」這種需求，小模型很可能寫出 `廣播 海綿城市` 之類不存在的動作行（說明裡沒有），或完全忽略時間點。
- 不知道旁白計多少秒，片長容易一直差幾秒來回改。

**改善建議**
- 報告加 `sceneSeconds: [{名稱, 開始, 長度}]`，並在說明寫出「旁白／說」自動計時公式。
- Story Spec 支援 `"廣播": "海綿城市"`（場景層級的訊息名稱），讓換場訊息用作者指定的名字，對應競賽要求的「廣播結構」。
- Story Spec 也接受「做不到」，並在報告輸出 `unsupported`。

## 12. 【遊戲】筏子溪：《石虎過河：筏子溪生態廊道》

**結果**：status `success`、playtestStatus `pass`、**2 關**（第一關：碰到「筏子溪河床」終點；第二關：收集 8 棵樹苗，分數 >= 80）。建置 4 次。

**與提示詞的差距**
- 空白鍵跳躍 → 平台移動固定上鍵跳，說明頁改寫「上鍵跳躍」。
- 「種植 8 棵樹」→ 沒有放置物件的行為，改成收集 8 棵「樹苗」（各 10 分）。
- 「血量」→ 用內建「生命」3 條。
- 「車流」→ 用左右巡邏的「汽車」（可踩扁）代替，不是持續行駛的車流。
- 廣播 [過關]、跳躍重力物理腳本、關卡切換廣播 → 由工具自動產生，不能指定名稱，也無法讓學生看到「自己寫的」結構。
- 標題與說明第一行都有「台中筏子溪石虎生態廊道」。

**不好用的地方**
1. **規則中的中文逗號被當成動作分隔**：`"開始 → 說 我要穿過車道，回到筏子溪河床！"` 產生 `看不懂動作「回到筏子溪河床！」，已略過`。說明只寫「動作, 動作」，沒說「說」的文字不能有逗號（全形也算）。
2. **「做不到」每一條都變成 feedback 警告**，而且建議是「→ 這部分需要新的行為，或改用進階模式自己寫積木」。照規則 2「照 feedback → 的建議修改」，小模型會以為要刪掉做不到或去找「進階模式」；但說明明明要求寫做不到。這 5 行雜訊淹沒了真正的錯誤。
3. **試玩失敗的提示誤導**：第 1～3 次都是「換關／第一關過關後沒有進入第二關」「進入第二關後地圖沒有換」。實際原因是**試玩機器人過不了第一關的障礙**（trace 顯示一直在 x≈50 附近被重生）。我只能去讀 `src/spec/scenario.ts` 才知道機器人會在 99 條命下自己走第一關，而第二關（分數過關）是直接把分數設定好，不是真的玩。最後把跳躍改「高」、速度改「快」並減少障礙才通過。
4. 更奇怪的是同一份地圖「通關」情境顯示 pass，「換關」情境卻 fail，兩者 trace 看起來都沒走到終點，讓人無法判斷哪個可信。
5. 第二關以分數過關時，試玩**沒有檢查 8 棵樹苗是否都拿得到**（直接設分數），所以地圖上樹苗放在跳不到的位置也會 pass。
6. 說明超過 22 字會出警告，但規則沒寫在 `guide` 中，是建置後才知道。

**小模型會卡住的地方**
- 「說 …」文字裡放逗號（中文模型幾乎一定會）。
- 看到「第一關過關後沒有進入第二關」會去改「過關」條件或關卡格式，而不是改地圖難度／跳躍高度，可能在 4 次內修不好。
- 要求「空白鍵跳躍」時，可能硬寫 `{"平台移動": {"按鍵": "空白鍵"}}` 之類不存在的參數。

**改善建議**
- 「說」的文字允許逗號（只用 `,` 半形加空白或改用陣列分隔動作），或 guide 中明寫。`guide` 也應列出物件寫法 `{ "當": …, "做": [...] }`（範例 `platformer.json` 有用到，guide 沒寫）。
- 「做不到」改成資訊等級（`info`），不放進 feedback，或改用不含「→ 改用進階模式」的文字。
- 試玩失敗時說出真正原因：「自動玩家在第一關 x≈50 處反覆失去生命，可能跳不過『汽車』『鐵絲網』→ 把跳躍改高、拉開障礙距離」。
- 平台移動支援 `跳躍鍵: 空白鍵`。
- 分數過關的關卡，靜態檢查收集品是否可達。

- `guide story` 附一份「保證可用」的角色、音效清單（或 `guide assets` 指令）。

**結果**：status `success`、playtestStatus `pass`、**2 關**（第一關：收集 3 個防砂壩魚道，分數 >= 30；第二關：清除 5 處泥沙，分數 >= 80），設定時間 40 秒、生命 3。建置 1 次即通過。

**與提示詞的差距**
- 「水溫變數」：guide 的規則沒有自訂變數（AGENTS.md 說有「自訂計數器」，但 guide 沒寫怎麼用），改成碰到「高溫淺灘」扣生命。

- 「產卵、廣播 [勝利]」：分數達標時「說 成功產卵！」，同時過關（工具自動顯示過關畫面；說話可能來不及看到）。
- 「40 秒內」只限第一關：`設定.時間` 是全遊戲設定，guide 沒說每關是否重新計時，無法只套第一關。

**不好用的地方**

- 每關計時、分數「累積」規則（第二關門檻要比第一關高）要靠自己算。

**小模型會卡住的地方**
- 很可能寫 `"水溫": 20` 或 `"變數": {...}` 這類不存在的欄位；或在規則條件寫 `水溫 > 30`。
- 第二關過關分數忘了要加上第一關累積分數（寫成 `分數 >= 50`，第二關開場就直接過關）。
- 地圖每列長度必須一致（20 字），手數 `#` 和 `.` 很容易差一格。

**改善建議**
- 開放 AGENTS.md 提到的「自訂計數器」到 guide（例如 `"計數器": {"水溫": 20}`，條件 `水溫 >= 30`，動作 `水溫 +1`），並能顯示在畫面上。
- 關卡層級的 `時間`。
- 分數門檻可寫「本關分數」，或在說明中舉出累積計算例子；建置時若第二關門檻 ≤ 第一關，直接報錯（目前是否有檢查不明）。

## 整體

**最常見的問題**
1. **競賽提示詞的「第 N 秒發送廣播 [名稱]」五件都碰到**（三件動畫、兩件遊戲），工具都做不到；動畫只能盲調秒數，因為報告沒有逐幕時間。
2. **回報資訊不足或誤導**：音效找不到時建議改成同一個名字；外觀找不到完全不報；試玩失敗只說「沒進入第二關」，不說機器人卡在哪裡。
3. **「做不到」處理不一致**：遊戲把它當警告塞滿 feedback（還建議「改用進階模式」）；動畫則靜默忽略。
4. **說明文件與實際格式有落差**：規則的物件寫法、說明 22 字上限、說話文字不能有逗號、自訂計數器，都沒寫在 guide。
5. `--silent` 仍有大量 stderr 警告，小模型若讀合併輸出會被淹沒。

**最想要的 3 個新功能**
1. **自訂名稱的廣播與時間點**：動畫場景可寫 `"廣播": "海綿城市"`，報告列出每幕開始秒數；遊戲過關／換關可指定廣播名稱。這是游智盃提示詞的固定要求。
2. **自訂變數／計數器**（水溫、血量、平衡值），可顯示在畫面、可用在規則條件與動作，並可設定每關計時。
3. **素材解析回報**：報告列出每個角色／音效實際用到哪個官方素材或退回簡單圖形，加上 `guide assets` 列出可用（已快取）名稱。

（其次：試玩失敗時回報自動玩家卡住的位置與原因；平台移動可改跳躍鍵；分數過關的關卡檢查收集品是否可達。）
