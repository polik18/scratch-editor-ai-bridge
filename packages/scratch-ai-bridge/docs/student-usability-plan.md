# 學生可用性驗收腳本

狀態：研究腳本已準備；尚未招募或進行學生測試。這份文件只定義如何驗收，不代表學生已完成測試。

## 目的

確認第一次使用 Scratch AI Bridge 的學生能否理解「描述作品 → 取得 AI 回覆 → 檢查並製作 `.sb3`」，並能辨認錯誤回饋、下載結果和分析既有專案的下一步。

`student-help.html` 是另一個只供學生解惑的入口，驗收時需另外測它的「上傳作品 → 找到程式線索 → 問問題 → 取得一步提示／複製給 AI」流程。不能以主工具的操作結果代替此頁驗收。

測試學生流程本身，不評分 Scratch 能力或作品創意。若測試需要使用外部 AI 服務，先由帶領者準備一份符合任務的回覆，避免把 AI 品質、帳號建立或服務速度混入 Bridge 評估。

## 執行方式

- 建議 5 位尚未使用過本工具的學生，逐位進行，每位約 15–20 分鐘。
- 在校內適用的家長／學校同意與隱私規則完成後才開始；不記錄姓名、帳號或其他個人資料。
- 以測試 fixture 和虛構角色名稱操作；不要貼入真實姓名、班級、聯絡方式或學生作品原文。
- 記錄每項任務是否完成、耗時、求助次數、誤解點和學生說出的困惑。錄影或錄音須另行取得明確同意；不同意不影響參與。
- 帶領者先讀任務，不示範按鈕位置。學生停滯時只問「你現在想做什麼？」；記錄提示後再繼續。

## 任務

1. **開始建立作品**：請用「讓小船用方向鍵移動，碰到星星時加一分」開始建立作品，並說出下一步要把哪段內容交給 AI。
2. **完成有效回覆**：把準備好的有效 AI 回覆貼入工具，完成檢查與 `.sb3` 下載，指出下載完成後如何在 Scratch 繼續編輯。
3. **理解修復訊息**：貼入含有一個未知積木的回覆。請說明工具正在要求 AI 修正什麼，再使用準備好的完整修正版完成重新檢查與下載。
4. **分析既有作品**：載入測試用 `.sb3`，找到一項分析提醒，說明它代表什麼，並指出如何保留原始專案或下載明確標示為 VM 正規化的版本。

任務 3、4 可在時間不足時分開進行，但要分別記錄，不能用其中一項替代另一項的結果。

## 學生解惑頁附加任務

使用一份不含真實學生資料的測試作品。主持人只說「請找出角色為什麼一開始在右邊」，不指出頁面按鈕或程式積木的位置。

1. 上傳 `.sb3`，說出畫面顯示的角色和程式位置；在 Scratch 中找到對應的角色、綠旗程式與定位積木。
2. 使用頁面提示檢查定位積木的 X/Y 數值，說出自己預期角色會出現在哪一側；在測試副本中改一個值並重新執行，描述看到的變化。
3. 複製 AI 提示（可由主持人貼入預備好的 AI 對話），判斷回覆是否只談作品線索、有沒有要求一次做太多事，以及是否照著提示就能找到積木。
4. 若作品含未知擴充積木，請學生說明工具是看不懂該積木，還是判定學生寫錯；觀察頁面是否避免替未知積木猜功能。

此附加任務共用前述記錄欄位與 5 人門檻。至少 4/5 位學生應能不經位置提示找到目標積木並指出數值；不得有學生把未知 extension 誤認為作品錯誤或把靜態分析誤認為作品已執行。未達標時修正學生頁／提示並重測。自動化瀏覽器 smoke 只驗證頁面有顯示對的線索，不取代這項真人任務。

## 每項任務記錄

| 欄位     | 記錄方式                                       |
| -------- | ---------------------------------------------- |
| 完成     | 獨立完成／收到提示後完成／未完成               |
| 時間     | 從讀完任務到完成或放棄，記錄分鐘與秒           |
| 求助     | 提示次數與提示內容，不記姓名或自由輸入作品文字 |
| 錯誤理解 | 學生對按鈕、警告、下載檔或資料保存的原話摘要   |
| 信心     | 任務後以 1–5 分自評「我知道下一步怎麼做」      |

## 通過門檻

- 至少 4/5 位學生能在不獲按鈕位置提示下完成任務 1–2，且兩項合計不超過 12 分鐘。
- 至少 4/5 位學生能正確說明 `.sb3` 下載後要在 Scratch 開啟／匯入，且不把 AI 回覆誤認成已自動送到 Scratch。
- 所有學生都能區分可下載的保留原始資料副本與 VM 正規化輸出；若有人混淆，記為資料完整性高優先修正，不以平均分抵銷。
- 任務 3 中，至少 4/5 位學生能辨認修復訊息要求貼回完整修正版；不得有人因文字暗示而以為已在伺服器自動修好。
- 任務 4 的分析提醒若被至少兩位學生誤解，新增對應的學生用說明並重新測該任務。

任何未達門檻的項目都建立具體 UX issue、修改介面後重測；不可用「學生喜歡」等泛泛回饋宣告通過。

## 測試後交付

- 匿名彙總任務完成率、時間範圍、提示數和重複誤解點。
- 只記錄可重現的 UI 問題及對應修正，不保存學生姓名、真實需求文字、帳號、AI 對話或原始作品。
- 在 `docs/status.md` 記錄實際日期、參與人數、通過結果和未解問題；沒有實測時維持「未完成」。
