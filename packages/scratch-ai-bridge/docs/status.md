# Scratch AI Bridge implementation status

## 2026-10-15 — CLI/agent/class-batch plan

Added `docs/cli-agent-plan.md`: the CLI should itself analyze, score and produce student-friendly evidence-based feedback offline, while coding agents invoke it directly without manual copy/paste or a Gemini-specific integration. Scope also includes agent-authored Canonical IR validation/compilation to SB3, safe patching of existing SB3, JSON/JSONL/Markdown output, and anonymous whole-class batch reports. Plan only; CLI implementation has not started.

## 2026-10-15 — SB3-only scoring first implementation

Implemented the first local scoring slice: `createProjectScore()` returns a repeatable `sb3-static-v1` 100-point result with six criterion scores, evidence IDs, import coverage, and static-analysis limits. The Analyze UI now shows the total and per-criterion evidence links. A separate copy action creates a Gemini coaching prompt that carries the fixed score and anonymized evidence; Gemini is instructed not to change the score or invent runtime/test results. No SB3, costume/sound bytes, or original sprite names are included in the copied packet. Unknown blocks are reported as a coverage limitation. This remains a provisional rule-based estimate: tests, lint/build, teacher calibration, and student usability review were not run in this task.

## 2026-10-15 — SB3-only student scoring plan

Defined a proposed 100-point rubric that uses only evidence inside the uploaded `.sb3`: observable project behavior/structure (25), program logic and flow (25), state/data use when applicable (15), interaction/feedback design (15), statically verifiable integrity/risk (15), and script organization/readability (5). It does not require an assignment prompt, questionnaire, test log, or reflection. Testing, runtime stability, student understanding, creativity, and aesthetics are excluded because the SB3 alone cannot establish them. Every score must cite project evidence; unsupported blocks reduce analysis coverage confidence and are not treated as student errors. Bridge computes the score deterministically; Gemini only explains the supplied score/evidence. This is a design proposal, not implemented or teacher-calibrated.

## Generic Scratch block graph (roadmap Phase 2)

Status: generic raw-graph preservation gate implemented; Canonical IR projection remains intentionally bounded.

- `extractProjectBlockGraphs()` copies every target's raw block graph without filtering unknown opcodes, mutation, comments,
  or extension fields.
- `replaceProjectBlockGraphs()` validates and writes replacement graphs back by target identity while preserving other project
  JSON fields.
- `decompileSb3WithBlockGraphs()` returns source graphs and a separate VM-derived Canonical IR projection; the upload UI uses
  this combined path for analysis.
- `validateScratchBlockGraph()` reports missing block/parent references, duplicate child references, multiple or inconsistent parent ownership, and cycles across `next` and nested inputs,
  malformed serialized input descriptors, and non-string `parent`/`next` references. It accepts SB3 descriptor kinds 1/2/3
  and inline primitive kinds 4–13, including variable/list/broadcast forms; substack inputs must begin with nested non-shadow blocks.
  It also rejects empty opcodes, non-object `fields`, malformed `mutation`/`shadow`/`topLevel` values, and non-finite x/y positions
  while leaving unknown extension node properties untouched.
- Procedure definitions must own one prototype whose proccode and argument ID/name/default arrays agree; procedure calls must
  resolve by proccode within the same target. Scratch VM can load an orphan call as a no-op, but this validator reports it as an
  unresolved structural dependency.
- Procedure calls must carry matching argument IDs and input names, and argument reporters must resolve to a declared argument
  in their containing procedure. Both current and legacy shadow-prototype layouts are covered.
- The graph copy/replace path preserves stable project signatures across all classified non-parse-only official SB3 fixtures.
- Compiler and decompiler now use the shared `graph/codec.ts` for Canonical IR v1 tree ↔ ID-linked block graph conversion;
  this projection does not carry opaque unknown fields, which remain preserved in the separate raw graph snapshot path.
- SB3 analysis inspects the raw archive graph alongside the VM-derived Canonical IR and reports preserved block counts,
  unmodeled opcodes, and graph structural issues.
- `mergeScratchBlockGraph()` applies node-level raw edits while preserving omitted properties and opaque fields; `null` deletes a
  node, and the merged graph must pass the invariant validator. Nested `inputs`, `fields`, and `mutation` are replaced as units.
- `patchProjectBlockGraphs()` scopes edits by target identity. `patchLosslessSb3BlockGraphs()` applies those edits to an imported
  archive, and `exportLosslessSb3()` writes the new `project.json` while retaining all other entry bytes; verified by re-import.
- The Canonical projection maps Scratch primitive kinds 4–13 and honors a type-3 descriptor's shadow fallback when its active
  value is empty; known menu shadows resolve through block capabilities. The separate raw graph keeps all opaque details.
- `CanonicalOpcode` accepts arbitrary strings and `KnownOpcode` names supported capabilities. The structural schema can carry an
  unknown opcode for preservation workflows, while semantic validation emits `unknown-opcode` and the compiler refuses it.
- The raw graph API remains separate from Canonical IR v1; the latter is a bounded tree projection, not an opaque shadow/extension
  preservation format. The first target-scoped AI patch prompt/UI/export flow is implemented over the raw graph path. Procedure definition/prototype/body/call compile-decompile now
  has initial slices, including named call input/argument ID mapping and procedure-scoped argument reporters. Recursive call graphs
  round-trip through the VM, and the legacy shadow-prototype layout imports to the same Canonical IR. The official mixed-extension
  `pen-dolphin-3d.sb3` fixture verifies 19 procedure definitions, 31 call sites, every parameter name/kind/default and warp flag, graph invariants, and all 13 numeric-only `%n` parameters. Canonical now represents `%n` as `number` and preserves it through compile/decompile; no lossy numeric-kind report is emitted. A five-level
  terminating countdown has a bounded Scratch VM execution assertion for both warp settings using the numeric-only `%n` parameter kind. Additional bounded runtime checks exercise string/boolean argument delivery and conditional execution, forward a string from one custom procedure into another, and confirm raw Scratch VM call blocks use string/boolean prototype defaults when serialized inputs are absent. A three-procedure mixed-warp chain verifies nested string/boolean defaults when an inner raw call omits both inputs; a recursive case verifies omitted boolean defaults with warp both on and off. Canonical IR still requires explicit call inputs; additional typed recursive/default combinations remain open. The normalization report identifies legacy prototype conversion,
  old shadow-prototype conversion and procedures skipped for invalid metadata. Unknown-opcode raw editing uses
  the patch/export API, while strict Canonical compilation rejects unsupported blocks.
- The fixture matrix now includes upstream `load-extensions/confirm-load/pen-dolphin-3d.sb3` and continues to cover
  `top-level-reporters.sb3` and `broadcast_special_chars.sb3`; a synthetic unknown-opcode SB3 round-trip verifies opaque graph
  fields and non-project archive assets survive a local patch. Upstream unknown-opcode fixtures are SB2 only. Procedure checks cover definition and prototype metadata,
  target-local call resolution, call inputs, and nested argument reporters.
