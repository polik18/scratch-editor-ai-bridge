# Bridge 小上下文 AI 執行入口

本入口是[總體計畫](../BRIDGE-IMPROVEMENT-PLAN-2026-11-02.md)的精簡執行層；目標、限制與驗收以總體計畫及適用指令為準，不代表實作已完成。狀態以[執行狀態](../BRIDGE-EXECUTION-STATUS.md)為準。任務卡非實時狀態。

> **文件導覽標記**：本目錄的總體計畫、執行狀態與任務卡是歷史參考，現行作品品質主線唯一入口為套件的 [`game-quality-plan.md`](../game-quality-plan.md)。請勿以本頁或其舊狀態欄接手目前進度。

## 每次啟動

1. 先遵守執行環境規定的啟動及 `AGENTS.md`。讀本頁、執行狀態與**一張**當前任務卡；不把整份總計畫、完整測試日誌或大型 SB3 放進上下文。遇到契約疑點，用 `rg -n` 搜關鍵字，按行數少量讀取總計畫相關小節。
2. 查 `git status --short`、`git log -1 --oneline`、`node --version`。保留既有未提交檔案；工作樹或 checkpoint 有新資料時先讀新資料。確認依賴和可用工具，若不足以安全做當前卡片，記錄原因並繼續不受影響的工作。
3. 先定位精確函式與既有測試，再增加會失敗的回歸、修改、跑相關測試。每次只處理一個小切片；不要大範圍改名、覆蓋原檔、清理其他人的資料或自動放寬安全限制。
4. 完成後更新執行狀態：日期、HEAD／dirty 摘要、工作項目、變更、命令與退出碼、證據、未測與下一步。長輸出寫本機外部檔案，只保留摘要和路徑；狀態檔不可含私有作品、完整素材或密鑰。
5. 超出單輪上下文時先記錄「下一個精確動作」再交接；下一輪從狀態檔恢復。除非使用者或適用指令明確要求，單一 AI 按依賴順序執行，不假設可以並行。

## 狀態和交付

狀態用「未開始／進行中／通過／受阻」；測試分別記 pass／fail／not-run 及原因。不能把局部測試、產檔或模擬模型當成整體驗收；不宣稱尚未執行的瀏覽器、真實模型、學生或 Scratch 官網驗證。依任務卡做完切片後，仍須照總計畫運行適用的整合驗收。
