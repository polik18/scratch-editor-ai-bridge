# 游智盃 30 題實作：工具好不好用的紀錄與改善清單

2026-11-11。把第八屆廣達游智盃「與我『河』關？」的 30 個提示詞（15 部動畫、15 個遊戲）交給 Scratch AI Bridge 實際做出來。
做法分兩路：

- **大模型**：6 個 Claude 子代理，每個做 5 件。照 `AGENTS.md` 和 `guide` 自己寫描述、建置、試玩，**不改工具程式**，
  並逐件記錄卡住的地方。
- **本地小模型**：Cyber-Tiel-Coder-35B（oMLX，關閉思考），把提示詞原文交給 `make`／`make --story`，最多修正 2 輪。

原始紀錄在 `research/youzhi-2026-usability/`。作品在不進 git 的 `output/游智盃/games/` 和 `output/游智盃-小模型/games/`。

## 1. 結果

| | 建置成功 | 試玩通過 | 第一次就成功 |
| --- | --- | --- | --- |
| 大模型（30 件） | 30 | 28（2 件是試玩誤判，見 U3） | 多數 1～3 次 |
| 小模型（30 件） | 25 | 23 | 動畫 0／15、遊戲 6／15 |
| 小模型：動畫 | 14／15 | 14 | 0（第一輪全部卡在背景名稱，見 S1） |
| 小模型：遊戲 | 11／15 | 9 | 6 |

大模型的動畫片長都落在指定秒數 ±2 秒內（85～130 秒）。

**「通過」不等於符合提示詞。** 提示詞要求的平衡值、拖曳、第 N 秒廣播、造型切換、特效，大多只能用「收集＋分數」近似，
或寫進「做不到」。試玩只檢查工具自己產生的玩法，不檢查是否符合提示詞。

小模型版失敗的 5 件：

| 號 | 原因 |
| --- | --- |
| 6、27 | 第二關過關分數沒有比第一關高（分數會累積） |
| 8、16 | 寫了兩個玩家角色（感測器＋水閥、竹筏＋擺渡人），而且地圖超過 20 欄 |
| 24 | 三輪都輸出不合法的 JSON |

另外 12、20 號雖然建置成功，但自動玩家到不了終點，試玩沒有通過。

## 2. 問題清單

編號依影響排序。「次數」是 30 件中碰到的件數，或 6 組中提到的組數。

### U1 動畫無法對準時間點（15 部動畫全部、6／6 組）
- 提示詞幾乎都寫「第 N 秒發送廣播 [名稱]，換背景」。工具既不能指定換場秒數，報告也只給總長，看不到每一幕從第幾秒開始。
- 子代理只能估算旁白長度倒推，甚至另做「探測建置」來反推（26、28 號）。
- 「說」和「旁白」的自動秒數怎麼算，沒有寫在說明裡。
- **改善**：報告列出每一幕的開始秒數和長度；場景可以寫 `"開始": 60` 或 `"長度": 50`，由工具自動補上等待；
  `guide story` 寫出自動秒數的公式。

### U2 沒有自訂廣播（30 件全部要求）
- 提示詞都要求「廣播 [切換現代]」「廣播 [過關]」這類有名稱的廣播，也要求輸出廣播鏈。工具內部用 `scene-1`、`_level-done`
  這類固定名稱。動作行寫「廣播 …」時，「廣播」反而被當成一個新角色建立（group-5）；遊戲規則寫「廣播 勝利」會被略過（小模型 27 號）。
- **改善**：場景和關卡可以寫 `"廣播": "切換現代"`，換場或過關時就用這個名稱；規則動作支援 `廣播 名稱`，條件支援 `收到 名稱`。

### U3 試玩誤判，feedback 指錯方向（大模型 2、4、10、12、20、27、29 號）
- **只在第一關測**：點擊目標只放在第二關時，試玩卻在第一關點，得分 0 → 判失敗（2、10、20 號）。feedback 說「可能沒有出現，或出現時間太短」，
  照著改反而破壞關卡設計。
- **測法不合物件的動向**：向左飄的掉落物，試玩用左右移動去接，平台玩家永遠接不到（4 號）。
- **自動玩家太簡單**：不會跳上懸空平台（4 號）、跳不過障礙（12 號）、被巡邏敵人擋住（29 號，兩行 feedback 還互相矛盾）。
- **沒有玩家的關卡也測移動**：點擊關卡地圖沒有牆，報「穿過了牆」（27 號）。
- 真正原因只在 `_過程/*.report.json` 的 `trace` 裡，feedback 沒寫。
- **改善**：
  - 每個情境改在角色真的出現的那一關測。
  - 依物件的移動方向決定試玩的測法。
  - 試玩失敗時，在 feedback 寫出「自動玩家停在 (x, y)，被『電魚網』擋住」。
  - 沒有玩家的關卡不做移動測試。
  - 用分數過關的關卡，要檢查收集品真的拿得到，而不是直接把分數設好。

### U4 feedback 的「→」不能照做或會誤導（6／6 組）
- 每一條「做不到」都附「→ 改用進階模式自己寫積木」，但沒有任何說明提過進階模式。AGENTS.md 的規則是「照 → 修改」，小模型會原地打轉。
- 背景名稱寫錯時，連帶冒出「沒換背景」「主角沒出場」「片長太短」三個假錯誤（group-5；小模型 S1 也是這個連鎖）。
- 音效找不到時，建議改成和範例一樣的名稱。**`guide story` 的範例 `播放 Water Drop` 本身就是錯的**，官方名稱是 `Water Drop 1`。
  這是 Bridge 自己的錯。
- 規則「說」的文字裡有全形逗號，會被切成兩個動作，後半句被丟掉。錯誤位置還標成第一關，其實是外層規則。
- `場景[1]` 從 1 起算，容易被當成 JSON 索引而改錯幕。
- **改善**：「做不到」只列在報告的 `unsupported`，不放進 feedback；只在 feedback 列出根本原因，不列連帶錯誤；
  修正 `guide story` 的範例；「說」的文字可以含逗號；位置改用「第 1 幕」這種寫法。

### U5 重要的事沒有說（5／6 組）
- 外觀名稱找不到時，靜靜換成人物造型，feedback 是空的。例如 `Flamingo`、`Rowboat`、`Train`、`Bus`，用 `Xyzzy` 測也一樣。
- 動畫描述的「做不到」欄位被直接忽略。
- 掉落物寫在某一關的圖例裡沒有作用，而且每一關都會出現，也沒有任何警告。
- **改善**：外觀和音效沒有精確對應時，一律寫進 feedback 並建議最接近的名稱（素材計畫 A 階段的 `describePick` 已經能產生這種訊息）；
  動畫支援「做不到」；角色只寫在某一關時給警告。

### U6 `guide` 不完整，但 AGENTS.md 說它「已包含全部格式」（6／6 組）
- 只寫在 `docs/guide/*.md` 或範例檔的功能：自訂計數器（`水位 +2`、`水位 >= 20`）、規則的物件寫法 `{當, 做}`、遊戲角色的外觀欄位。
- 沒寫在任何地方的規則：說明每行 22 字、第二關分數要累積、時間是否換關重設、點擊目標點到後會不會消失、旁白可以加 N 秒、片尾前的淡出。
- 速度用詞前後不一致：一處寫「慢／中／快」，另一處寫「低／中／高」。
- **改善**：`guide` 補齊所有功能和隱性規則；在測試裡檢查 `guide` 有提到每一個行為、欄位和動作。

### U7 關卡不能各自設定（大模型 4 組、小模型 S5）
- 時間是整場共用，不能「第一關限時 30 秒」。
- 掉落物和子彈每一關都會出現。
- 玩家移動方式和背景整場都一樣，做不到「第一關上下游、第二關跳躍」或「第二關只點擊、沒有玩家」。
- 分數跨關累積，第二關的過關分數要自己加總，小模型 7 次寫錯。
- **改善**：每一關可以寫 `時間`、`背景`、`玩家`，以及要出現的角色；新增「本關分數」，或「收集 X 達 N 個 → 過關」這種計數條件。

### U8 缺少常見的遊戲機制（30 個遊戲提示詞的核心需求）
| 機制 | 提示詞 |
| --- | --- |
| 拖曳／放置 | 6、8、10、20、22、27 |
| 按鍵觸發動作（空白鍵挖沙、採集） | 2、16、25 |
| 自訂數值顯示（平衡值、水溫、pH、百分比） | 8、10、14、16、27 |
| 「維持 N 秒」條件 | 8、20 |
| 搬運／送達 | 16、30 |
| 平衡、物理模擬 | 16 |
| 跟著滑鼠移動的玩家 | 18 |
| 用空白鍵跳 | 12 |

自訂計數器其實有支援，只是 `guide` 沒寫，見 U6。

### U9 動畫缺少的動作（15 部動畫）
- 換造型，例如「老渡船伯換成現代裝扮」。
- 字卡，也就是畫面上的標題文字。
- 圖像特效：背景變亮、沙塵、閃光。
- 指定換到哪一張背景、背景淡入淡出的方式。

### U10 素材要用猜的（6／6 組）
- 沒有可以查的角色、背景、音效名稱清單；子代理猜過的 Wind、Whoosh、Flamingo 都不存在。
- 報告不寫每個角色實際用了哪個素材。
- 常見題材沒有素材：龍舟、橋、攔河堰、紅樹林、竹筏、污染的河川、瀑布、各種台灣鳥類。
- **改善**：素材計畫 B、C 階段：把 `pickSprite`／`pickBackdrop`／`pickSound` 接到遊戲和動畫，提供 `assets search` 和 `guide assets`，
  並在報告列出每個角色用了哪個素材。

### U11 主題關鍵字沒有檢查
- 競賽規定河流名稱必須出現。工具不會檢查，名稱是否真的出現在標題、說明或對白，只能自己看。
- **改善**：新增 `"必須出現": ["淡水河"]` 欄位，檢查標題、說明、對白和旁白裡至少出現一次。

### U12 輸出雜訊（6／6 組）
- 加了 `--silent`，stderr 仍印出幾十行 scratch-vm 的 WARN，JSON 報告被埋在最後。每個子代理都要自己加 `2>/dev/null`。
- **改善**：建置時把 VM 的記錄一律收起來，只在 `--verbose` 時顯示。

### U13 輸出位置的意外（2 組）
- 描述檔不在 `output/games/<名稱>/` 裡時，`.sb3` 會依標題另開資料夾，不在描述檔旁邊，試驗時留下多餘的資料夾。
- 設定 `SCRATCH_BRIDGE_OUTPUT_DIR` 會連素材快取一起換位置，看起來像離線、找不到素材。
- **改善**：任何位置的描述檔，都把 `.sb3` 產生在它旁邊；素材快取固定放在 repo 第一層的 `output/cache/`。

### U14 待查證：點擊目標會不會重複得分
- group-4 回報 18 號「點同一隻招潮蟹得到 60 分」，認為點擊目標點了不會消失。
- 但程式碼在點擊後會刪除那個分身（`src/spec/compile.ts` 的 `clickable`）。可能是試玩的點擊方式、規則重複加分，或分身刪除的時機造成的。
- 下一步：用 18 號作品重現。

## 3. 小模型特有的問題

### S1 把 Backdrop1／Sprite1 當成名稱（14／15 部動畫）
- 提示詞寫「Backdrop1（清代淡水港）」，模型照抄成 `"背景": "Backdrop1"`。結果每部動畫第一輪都有 2 個「找不到背景」，
  再連帶「主角沒出場」「沒換背景」「片長不足」各 14 次。第二輪看了 feedback 才改好。
- **改善**：認得 `Backdrop1`、`Sprite1` 這類 Scratch 預設名稱，改用括號裡的描述；或在 feedback 直接說「Backdrop1 是預設名稱，請寫成背景的描述」。
  另外，素材計畫的 `pickBackdrop` 已經能把「清代淡水港」「人工濕地」這類描述對應到官方背景（近似）。

### S2 遊戲：只能有一個玩家（8、10、16 號）
- 提示詞有兩個操作對象（感測器＋水閥、淨化網＋擺放手、竹筏＋擺渡人），模型都寫成兩個玩家。
- **改善**：允許「滑鼠操作」的第二種角色；或在 guide 明確說明「只能一個玩家，其他用點擊」。

### S3 地圖超過 20 欄（8、12、16 號）
- 模型常寫 24～31 欄的地圖，被裁掉之後連終點都不見了。
- **改善**：寬地圖自動縮放或分段；guide 用範例示範 20 欄的寬度。

### S4 分數累積的規則（7 次）
- 同 U7，小模型幾乎不會自己加總兩關的分數。

### S5 JSON 格式錯誤（24 號連續 3 輪）
- 動畫描述很長，括號或逗號出錯的機率高。
- **改善**：讓動畫的寬容修正和遊戲一樣（遊戲已經會自動修正括號）；修正回合只回傳出錯的那一段。

### S6 好的地方
- 動畫經過 1 輪修正後 14／15 成功，片長都在 60～180 秒。
- 遊戲的說明頁、兩關和換關由工具自動處理，小模型不必懂就能做出符合規定的結構。
- 錯誤訊息都是中文、具體，而且有位置。

## 4. 提示詞本身的事實疑點（照原文保留）
- 3 號「截灣取直」應為「截彎取直」；「全世界著名的壺穴」偏誇大。
- 5 號「文湖線沿景美溪行駛」只有部分路段是這樣。
- 11 號「柳川以前是運河」、15 號「紅磚鐵橋」需要查證。
- 26 號把日本禿頭鯊稱為「小鮠魚」，但它是鰕虎科；「在海裡孵化」和一般資料（在溪裡孵化、仔魚降海）不符。
- 29 號「高山鯝魚」疑似「高身鯝魚」的錯字。
- 20 號把鳳山城的護城河和曹公圳的灌溉渠道混在一起。

## 5. 建議的優先順序

| 優先 | 項目 | 理由 |
| --- | --- | --- |
| P0 | U12 雜訊、U4 feedback 修正（含 Water Drop 範例）、U5 靜默替換、U6 guide 補齊、S1 預設名稱 | 改動小，大小模型都直接受益；目前會讓小模型原地打轉 |
| P0 | U3 試玩逐關測試、失敗說明原因 | 會讓正確的作品被判失敗，作者照錯誤建議修改 |
| P1 | U1 時間軸、U2 自訂廣播、U11 必須出現 | 30 個競賽提示詞都要求 |
| P1 | U7 每關各自設定、U10 素材（素材計畫 B、C 階段） | 決定遊戲能不能忠於提示詞、畫面好不好 |
| P2 | U8 新機制（拖曳／放置、按鍵觸發、數值顯示、維持 N 秒）、U9 動畫動作 | 工作量大，但能讓大部分「做不到」消失 |

U14 先查證再決定。
