## 目標與完成條件

讓 Hermes 能透過明確且可重複的流程建立、修改並儲存 Scratch 彈珠台，在 Camoufox 的 Scratch 編輯器中載入同一份作品、操作遊戲並核對結果。最終交付可重新開啟、可玩的 SB3、測試證據及操作文件。若 GUI 編輯後需交還 CLI，必須有經驗證的匯出與重新載入步驟；不得宣稱自動雙向同步，除非實際實作並驗收。

本機 8601 的 Scratch GUI 首頁已於 2026-10-31 由 Camoufox 開啟。現有 session 的 7 個角色缺少 md5ext，compile 可重現失敗；Ball 的積木尚不構成完整邏輯。Hermes 當次的命令、錯誤訊息及其環境尚未核實，不能先認定它打不開視窗的單一原因。

## P0：保護現況與重現 Hermes 入口

- 先確認專案工作樹、執行者與是否有其他工作正在修改；保留既有未提交程式、session、SB3 和圖片。測試使用獨立暫存目錄與副本，記錄原始檔 SHA-256；不覆寫原始檔。
- 在 Hermes 的實際工作目錄與執行環境，記錄命令、退出碼、錯誤、PATH、Node、Playwright 瀏覽器、8601 服務及是否有桌面顯示能力；不收集憑證。區分 session 找不到、服務未啟動、獨立視窗無法顯示、匯入失敗及命令等待視窗關閉等情況。
- 驗證 Camoufox 目前提供的操作，包括本機 GUI 導覽、舞台與積木可見性、輸入、匯入及匯出。現行 CLI help 沒有直接的檔案上傳命令，不預設檔案選擇器一定可由 Camoufox 自動化；先做可行性試驗，再決定是新增受控的 CLI 上傳能力，還是使用經驗證的本機匯入機制。遵守 status、唯一 task、lease、caller 與禁止繞過共享 profile CLI 的規則。
- 驗收：能附上實際重現步驟與錯誤；若故障無法重現，明確記錄限制，不把猜測當根因。

## P1：修正 session 封裝與素材

- 先寫失敗測試：新建專案、新增角色、封裝、驗證與 VM 載入；另涵蓋現有包含內嵌 data 的草稿、重複素材及匯入後未變更的 SB3。
- 在 session 素材建立／封裝邊界，依素材位元組建立一致的 assetId、md5ext 及 ZIP entry，使用 Scratch 相容格式；保留既有素材、音效與其他 ZIP entries。避免只補欄位或把 session 誤接到不同資料模型的 Canonical compiler。
- 既有草稿透過非破壞性的轉換或封裝支援修復；不靜默覆蓋原檔，缺失／格式錯誤素材要回報可定位的錯誤。
- 驗收：新角色與舊草稿均可產生完整 SB3；檢查每個引用存在且雜湊一致、VM 可載入；無修改的既有作品維持素材與專案語義。透明素材僅能作為暫用佔位，不能當彈珠台視覺完成。

## P2：修正積木建立與驗證

- 依本 repo 的 Scratch VM 實際序列化契約處理 input、shadow、field、parent、next 和控制積木的子堆疊。新增合理的 CLI 建立數值、條件與子堆疊方式，並對錯誤或不支援的操作提供明確診斷。
- 驗證器需辨識本次重現的錯誤：數值放錯位置、缺少控制條件／子堆疊、錯誤連線與跨角色引用等；既有合法作品不得被誤拒。不要以語法通過等同遊戲邏輯正確。
- 先建立包含綠旗、移動、forever、if、碰撞與條件的回歸測試；再用 VM 執行與 save/reload 驗證連線與行為。測試失敗時保留可診斷輸出。
- 驗收：錯誤草稿能被指出；有效積木可在 Scratch GUI 正確顯示並執行，不只通過自製 graph validator。

## P3：打通 Hermes 與 Camoufox 操作

- 根據 P0 實測選定一條可維護路徑：CLI 匯出經驗證的 SB3，Camoufox 透過受支援的方法在本機 Scratch GUI 匯入，操作並檢查；如需 GUI 編輯，明確匯出成新檔後讓 CLI 重新 load。確認匯出與重新載入後內容一致。
- 保留現有 Playwright `open` 的獨立視窗語義，文件清楚說明它不會接管 Camoufox、通常會等待視窗關閉，也不會自動同步；不要以啟動另一瀏覽器替代 Camoufox 的驗收。
- 加入服務未啟動、session 不存在、匯入失敗、檔案衝突及不支援操作的可行動錯誤訊息。明確說明工作目錄、啟動命令、headless／desktop 與檔案所有權；不依賴隱藏或未文件化的共用瀏覽器 API。
- 驗收：以 Hermes 的實際 caller 和獨立 task 完成一次 CLI 匯出、Camoufox 匯入、操作、儲存及重開；比對檔案及角色／積木。若 Hermes 執行環境不可用，標示未驗收，不以 Codex 測試冒充。

## P4：完成可玩的彈珠台

- 依副本重建或修復現有作品：提供可見的球、左右牆、底部、彈板與碰撞物，設定合理位置和大小；實作綠旗初始化、移動、重力或適當的速度變化、碰撞反彈、左右彈板控制、得分及落球／重新開始。設計應能在一般鍵盤操作下完成一局。
- 使用程式化或可重複的 VM 行為測試檢查初始化、移動、按鍵、碰撞、得分和落球；使用 Camoufox 實測載入、視覺與互動。保存測試步驟、必要截圖及驗收 SB3 的雜湊；截圖本身不能證明互動正確。
- 驗收：乾淨載入同一個 SB3 後，球與物件可見，鍵盤控制、碰撞、計分與落球可重複驗證；重新開啟仍正常。明確列出未達成的遊戲功能。

## P5：整合與交付

- 更新使用手冊與錯誤排除文件，標示真正支援的命令、素材與同步限制，修正已過時的 preview 說明；對照既有 `cli-agent-editing-plan.md` 與 SB3 計畫，避免重複宣稱已完成。
- 依 repo 規範執行受影響套件的測試、build 與 lint；失敗需記錄是否為既有問題及具體證據。完成後審查差異，保留其他人的未提交修改。
- 交付修復摘要、已驗證命令、結果與限制、產物路徑及下一步。只有 P1–P4 各項實測通過，才可宣稱 Hermes 能完成此互動工作流程。

## 執行順序與範圍

P0 先釐清真實入口與匯入能力；P1、P2 修正檔案與積木正確性；P3 建立操作交接；P4 完成遊戲；P5 彙整驗收。P0 的瀏覽器可行性結果可能影響 P3 設計。計畫不要求為此先建通用雙向同步系統，也不更動現有使用者作品或清理其他未提交內容。
