# Game Spec（作品描述）v0

給人或小模型寫的精簡作品格式：只描述「有哪些角色、各自有什麼行為、什麼時候發生什麼事、東西放在哪裡」。
Bridge 會把它編譯成 Canonical IR，再走既有的 Scratch VM 檢查；物理、碰撞、角色之間的溝通和初始化都由行為庫產生。

```sh
npm run cli --workspace=@scratch/scratch-ai-bridge -- spec 作品描述.json --out 新遊戲.sb3 --playtest
```

`--playtest` 會依作品描述自動產生試玩劇本（需要先 `npm run build`），在真正的 Scratch 預覽中按鍵、讀狀態並檢查結果。
輸出 JSON 的 `feedback` 是一行一個問題、附「→ 建議」的白話訊息，可直接貼回給模型修正
（`src/spec/prompt.ts` 的 `createGameSpecRepairInstruction`）。給模型的完整寫作說明見 `createGameSpecInstruction`。

## 格式

```json
{
  "標題": "寶石迷宮",
  "地圖": ["#######", "#P.o.G#", "#######"],
  "圖例": { "P": "勇者", "o": "寶石", "G": "出口" },
  "角色": {
    "勇者": { "行為": ["俯視移動"] },
    "寶石": { "行為": [{ "收集品": { "分數": 10 } }], "外觀": "star" },
    "出口": { "行為": ["終點"] }
  },
  "規則": ["收集 寶石 → 說 找到了！", { "當": "分數 >= 10", "做": ["說 全部找到了"] }],
  "設定": { "生命": 3 }
}
```

- **地圖**：最多 20 欄 × 15 列，每格 24 px；比舞台矮的地圖貼齊底部。`#`、`=` 是牆／地面，`.`、空白、`_` 是空地。
  圖例可把其他符號指定為牆（值寫「牆」「地面」「平台」）。同一符號可出現多次，每個位置都會產生一個分身。
- **圖例**：符號 → 角色名稱。角色名稱的第一個字若剛好是地圖符號，可省略圖例。
- **鍵名**：中英文都可（`title`／`標題`、`entities`／`角色`、`behaviors`／`行為` …），小錯字會自動修正並在診斷中標「已自動修正」。

## 行為

| 行為                  | 參數（預設）                             | 作用                                                                             |
| --------------------- | ---------------------------------------- | -------------------------------------------------------------------------------- |
| 平台移動 `platformer` | 跳躍 低/中/高（中）、速度 慢/中/快（中） | 玩家：左右走、上鍵／W／空白跳。跳躍「中」可往上 3 格、「高」5 格。掉出舞台扣命。 |
| 俯視移動 `topdown`    | 速度（中）                               | 玩家：上下左右走，牆會擋；差幾 px 對不準通道時自動對齊。                         |
| 巡邏 `patrol`         | 範圍 格數（3）、可踩扁（是）、分數（50） | 敵人左右來回。平台遊戲中從上方踩會消滅並加分，其他碰觸扣命。                     |
| 收集品 `collectible`  | 分數（10）                               | 玩家碰到就加分並消失。                                                           |
| 危險物 `hazard`       | —                                        | 玩家碰到扣一條命。                                                               |
| 終點 `goal`           | —                                        | 玩家碰到就過關。                                                                 |

一個作品只能有一個玩家（平台移動或俯視移動）。外觀可選 `hero`、`slime`、`coin`、`spike`、`flag`、`box`、`key`、`star`，
另可給 `顏色`；未指定時依第一個行為決定。

## 規則

`"條件 → 動作, 動作"`，或 `{ "當": 條件, "做": [動作] }`。

- 條件：`開始`、`收集 X`、`碰到 X`、`踩扁 X`、`分數 >= N`
- 動作：`分數 +N`、`生命 -N`、`說 文字`、`過關`、`失敗`

## 檢查與試玩

編譯前的遊戲檢查（`src/spec/check.ts`）用和遊戲相同的物理數值估算：玩家到不到得了每個終點和收集品，到不了就指出地圖位置
和要改的參數。平台遊戲的估算忽略天花板與移動中的敵人，所以結果是「注意」而非錯誤。

自動試玩（`src/spec/scenario.ts`、`src/cli/scenario-runner.ts`）依地圖產生：開場站穩、各方向移動或被牆擋住、跳起與落地，
以及一個簡單的自動玩家嘗試走到終點（俯視用最短路徑，平台遊戲朝終點走、遇到敵人／坑／卡住就跳）。自動玩家很簡單，
未過關時報告會附軌跡，不一定代表遊戲壞掉。
