# Game Spec（作品描述）v0

給人或小模型寫的精簡作品格式：只描述「有哪些角色、各自有什麼行為、什麼時候發生什麼事、東西放在哪裡」。
Bridge 會把它編譯成 Canonical IR，再走既有的 Scratch VM 檢查；物理、碰撞、角色之間的溝通和初始化都由行為庫產生。

```sh
npm run --silent bridge -- spec output/games/接蘋果/接蘋果.spec.json --playtest   # 在 repo 第一層執行
npm run --silent bridge -- make "一句話需求" --playtest                         # 本機模型寫描述
npm run --silent bridge -- guide                                               # 印出寫作格式
```

沒有 `--out` 時，遊戲放在 repo 第一層的 `output/games/<名稱>/`：`<名稱>.sb3`、`<名稱>.spec.json`，以及存放報告與模型回覆的 `_過程/`。
描述檔已經在某個遊戲資料夾裡時，`.sb3` 就產生在它旁邊；否則用「標題」當資料夾名稱。重建同一個遊戲要加 `--force`；被取代的 `.sb3` 和它當時的描述會先複製到 `_過程/舊版/<時間>/`。

三個入口用同一份寫作說明（`src/spec/prompt.ts` 的 `createGameSpecGuide`）：`make` 把它連同需求送給模型；`guide`
印給自己寫描述的 AI；MCP 工具 `make_game` 把它放在工具說明裡。`make` 在建置或試玩失敗時，會把 `feedback`
連同上一版描述送回模型修正（`--rounds`，預設 1 輪），並保留最好的一次。

`--playtest` 會依作品描述自動產生試玩劇本（需要先 `npm run build`），在真正的 Scratch 預覽中按鍵、讀狀態並檢查結果。
輸出 JSON 的 `feedback` 是一行一個問題、附「→ 建議」的白話訊息，可直接貼回給模型修正
（`src/spec/prompt.ts` 的 `createGameSpecRepairInstruction`）。給模型的完整寫作說明見 `createGameSpecInstruction`。

## 格式

```json
{
  "標題": "寶石迷宮",
  "地圖": ["#######", "#P.o.G#", "#######"],
  "圖例": { "P": "勇者", "o": "寶石", "G": "出口" },
  "角色": {
    "勇者": { "行為": ["俯視移動"] },
    "寶石": { "行為": [{ "收集品": { "分數": 10 } }], "外觀": "star" },
    "出口": { "行為": ["終點"] }
  },
  "規則": ["收集 寶石 → 說 找到了！", { "當": "分數 >= 10", "做": ["說 全部找到了"] }],
  "設定": { "生命": 3 }
}
```

- **地圖**：最多 20 欄 × 15 列，每格 24 px；比舞台矮的地圖貼齊底部。`#`、`=` 是牆／地面，`.`、空白、`_` 是空地。
  圖例可把其他符號指定為牆（值寫「牆」「地面」「平台」）。同一符號可出現多次，每個位置都會產生一個分身。
- **圖例**：符號 → 角色名稱。角色名稱的第一個字若剛好是地圖符號，可省略圖例。
- **鍵名**：中英文都可（`title`／`標題`、`entities`／`角色`、`behaviors`／`行為` …），小錯字會自動修正並在診斷中標「已自動修正」。

## 行為

| 行為                  | 參數（預設）                                             | 作用                                                                                         |
| --------------------- | -------------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 平台移動 `platformer` | 跳躍 低/中/高（中）、速度 慢/中/快（中）                 | 玩家：左右走、上鍵／W／空白跳。跳躍「中」可往上 3 格、「高」5 格。掉出舞台扣命。             |
| 俯視移動 `topdown`    | 速度（中）、方向 左右/上下/全部（全部）                  | 玩家：用方向鍵走，牆會擋；差幾 px 對不準通道時自動對齊。                                     |
| 巡邏 `patrol`         | 範圍 格數（3）、可踩扁（是）、分數（50）                 | 敵人左右來回。平台遊戲中從上方踩會消滅並加分，其他碰觸扣命。                                 |
| 收集品 `collectible`  | 分數（10）                                               | 玩家碰到就加分並消失。                                                                       |
| 危險物 `hazard`       | —                                                        | 玩家碰到扣一條命。                                                                           |
| 終點 `goal`           | —                                                        | 玩家碰到就過關。                                                                             |
| 掉落物 `faller`       | 速度、間隔 秒（1.5）、方向 下/上/左/右（下）、加速（否） | 不用畫在地圖上；從舞台邊緣不斷出現並移動，離開舞台時觸發「漏掉 X」。常和收集品或危險物合用。 |
| 子彈 `projectile`     | 按鍵（空白鍵）、方向 上/下/左/右/面向（上）、速度        | 不用畫在地圖上；按鍵時從玩家射出，打到「可射中」的角色。需要玩家。                           |
| 可射中 `target`       | 分數（10）                                               | 被子彈打到就得分並消失，觸發「射中 X」。                                                     |
| 點擊目標 `clickable`  | 分數（10）                                               | 用滑鼠點到就得分，觸發「點到 X」。可以沒有玩家角色。                                         |
| 冒出 `popup`          | 停留 秒（1）                                             | 在地圖位置上隨機冒出又躲回去。                                                               |

一個作品最多一個玩家（平台移動或俯視移動）；只有「點擊目標」的滑鼠遊戲可以沒有玩家。外觀可選 `hero`、`slime`、`coin`、`spike`、`flag`、`box`、`key`、`star`、`apple`、`rock`、
`balloon`、`bullet`、`car`、`mole`，另可給 `顏色`；未指定時先依名稱（例如「蘋果」「隕石」），再依第一個行為決定。

## 規則

`"條件 → 動作, 動作"`，或 `{ "當": 條件, "做": [動作] }`。

- 條件：`開始`、`每 N 秒`、`時間到`、`收集 X`、`碰到 X`、`踩扁 X`、`射中 X`、`點到 X`、`漏掉 X`，
  或任何變數比較 `分數 >= N`、`生命 <= N`、`氧氣 <= 0`
- 動作：`分數 +N`、`生命 -N`、`時間 +N`、`說 文字`、`過關`、`失敗`，或任何計數器 `氧氣 +3`

`設定.時間` 開啟倒數計時。規則中出現的新名稱（例如「氧氣」）會成為顯示在舞台上的計數器，`設定` 中同名的數字是開始值；
會減少或被檢查是否用完的計數器沒有開始值時用 10。`"做不到": [...]` 讓作者列出沒辦法做到的需求，結果會顯示在診斷中。

## 自動修正

作品描述的目標讀者包括小模型，所以只在作品真的無法運作時才拒絕；其他問題盡量修正並在診斷中標「已自動修正」，
或略過有問題的部分並標「注意」：

- JSON：外面的說明文字、括號錯配（缺少、順序顛倒、該放鍵名的地方開了物件）、多餘逗號。
- 欄位：中英文別名與錯字；寫進「角色」裡的「規則」「設定」等欄位移回外層；一個物件裡寫多個行為。
- 地圖：超出舞台時裁切（保留下方）；平台遊戲沒有地面時補一排；玩家、終點、巡邏敵人沒畫時自動放置；
  玩家起點下方沒有地面時移到最近可站的位置；沒畫在地圖上的收集品／危險物／可射中／點擊目標改成從邊緣出現。
- 角色：只在圖例出現的角色依名稱推斷行為；規則要點擊或射中的角色自動加上對應行為。
- 規則：看不懂的條件或動作只略過該條，「生命用完→失敗」視為內建。

## 開場說明與兩關

每個遊戲都會先顯示開場說明卡，內容包括標題、玩法和「按空白鍵或點一下開始」；按下後才開始計時和遊戲。
`"說明": ["…", "…"]` 可以自己寫說明，最多 6 行；沒寫的話，工具會依玩家移動方式、要收集或閃避的角色、
過關條件、生命和時間自動產生。

把 `地圖` 換成 `關卡` 就是兩關遊戲（最多 2 關）：

```json
"關卡": [
  { "名稱": "第一關 清澈溪流", "地圖": ["…"], "過關": "分數 >= 50" },
  { "名稱": "第二關 危險陷阱", "地圖": ["…"], "規則": ["碰到 陷阱 → 說 好險"] }
]
```

- 每一關有自己的地圖，也可以有自己的 `圖例` 和 `規則`；最外層的 `規則` 每一關都有效。
- `過關` 是「條件 → 過關」的簡寫。每一關都要能過關：寫 `過關`，或在這一關的地圖上畫一個「終點」角色，否則建置失敗。
- 角色只會出現在有畫到它的那一關。只畫在第二關的角色，不會被自動補到第一關，也不會被改成從天上掉下來。
- 分數會累積到下一關，所以第二關的過關分數要比第一關高。
- 第一關過關後，畫面會顯示第二關的名稱 2 秒，然後換地圖；最後一關過關才是「過關！」。
- `--playtest` 會檢查三件事：開場停在說明卡、第一關過關後進入第二關並換地圖、第二關過關後出現過關畫面。

完整範例：`src/spec/examples/two-levels.json`。

## 檢查與試玩

編譯前的遊戲檢查（`src/spec/check.ts`）用和遊戲相同的物理數值估算：玩家到不到得了每個終點和收集品，到不了就指出地圖位置
和要改的參數。平台遊戲的估算忽略天花板與移動中的敵人，所以結果是「注意」而非錯誤。

自動試玩（`src/spec/scenario.ts`、`src/cli/scenario-runner.ts`）依地圖產生：開場站穩、各方向移動或被牆擋住、跳起與落地，
以及一個簡單的自動玩家嘗試走到終點（俯視用最短路徑，平台遊戲朝終點走、遇到敵人／坑／卡住就跳）。行為的效果也會
自動檢查：移動到掉落物下方能得分、射擊能打中、漏接會扣命、點擊會得分、時間會倒數（自動玩家透過預覽的
`playtest-clones` 訊息看到分身位置；檢查接住與射擊時會先把生命暫設為 99）。自動玩家很簡單，未過關時報告會附軌跡，
不一定代表遊戲壞掉。
